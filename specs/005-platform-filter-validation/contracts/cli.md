# CLI Contract: algo-pick

범위는 [spec.md](../spec.md), typed 처리 경계는 [platform.md](platform.md)를 따른다.

## 진입점과 플랫폼 선택

```text
algo-pick [--platform PLATFORM] list [OPTIONS]
algo-pick [--platform PLATFORM] recommend [OPTIONS]
algo-pick [--platform PLATFORM] open ID [ID ...]
algo-pick --help
algo-pick --version
```

- PLATFORM 생략 시 `jungol`. 실제 선택 가능 값은 소문자 `jungol` 하나다.
- 플랫폼 옵션은 명령 앞의 공통 옵션이다. 명령 뒤의 같은 이름 옵션·대소문자/한국어 별칭은 추가하지 않는다.
- 빈 문자열·오타·미등록 값·`programmers`는 이름과 가능한 값 안내 후 코드 2. 정올로 대체하지 않는다.
- 배포 패키지 `algorithm-problem-picker`와 모듈 `algorithm_problem_picker`는 유지하고 설치 실행 키만 `algo-pick`으로 변경한다. `jpick` 호환 별칭은 제공하지 않는다. 업그레이드 전 환경에 남은 옛 launcher의 자동 삭제는 도구가 수행하지 않으며 새 설치 메타데이터로 검증한다.

## 필터와 값 검증

현재 공통 입력 표면은 정올의 `--tier/--rate/--accepted`, 각 `--min-*`·`--max-*`, `--status`, `--user`다. 플랫폼별 실제 지원 이름과 허용 값은 지원 정보가 결정한다.

| 순서 | 계약 |
| --- | --- |
| 1 | 기본 CLI 문법을 읽고 선택 플랫폼을 확인한다. |
| 2 | 필터 값 변환 없이 사용자가 명시한 모든 옵션 이름을 수집한다. |
| 3 | 미지원 옵션이 있으면 전부 식별할 수 있도록 플랫폼 이름과 함께 stderr에 알리고 코드 2로 중단한다. |
| 4 | 모두 지원할 때만 플랫폼 고유 값·조합을 검증한다. 무효이면 플랫폼 이름·옵션·이유를 stderr에 알리고 코드 2로 중단한다. |
| 5 | 유효한 경우에만 source factory를 호출하고 조회·사용자 식별·수집을 시작한다. |

기본값과 같은 값도 명시했으면 검사한다. 미지원 속성에 `--min-accepted 0`, `--accepted 0..0`을 요청해도 무시하지 않는다. `--status all` 명시와 생략은 다르다. 명시한 빈 `--user ''`도 옵션 요청이다. 값 오류·반복이 섞인 미지원 옵션도 지원 검사가 먼저다. 값 자체 누락이나 알 수 없는 옵션은 Typer의 기본 문법 오류로 코드 2를 반환한다.

정올의 폐기 옵션 `--min-solvers`·`--max-solvers`는 지원 필터가 아닌 별도 진단 대상이다. 알려진 폐기 입력은 해당 플랫폼의 기존 대체 옵션·지표 변경 안내를 제공한 뒤 코드 2로 거부한다. 새 필터의 별칭으로 적용하지 않는다. `--sort solvers`도 정올 정렬 검증에서 기존 전환 안내를 유지한다.

복수 미지원 예시의 정보 내용은 다음과 같다. 정확한 문장·옵션 출력 순서는 고정하지 않되 각 이름은 한 번만 식별하면 된다.

```text
합성플랫폼(test-platform): 지원하지 않는 필터: --accepted, --status
```

오류 실행에서 소스 팩터리·사이트 접속·사용자 조회·수집·브라우저 전달은 0회이고 결과 표·집계는 stdout에 출력하지 않는다. 유효하지 않은 비필터 옵션이 동시에 있을 때의 오류 우선순위는 고정하지 않는다.

## 정올의 보존 계약

- 지원 필터와 의미는 [정올 지원 필터 기준](../spec.md#정올-지원-필터-기준)을 따른다. 티어 약칭/숫자, 소수 정답률, 중복 정답 제출 포함 지표를 유지한다.
- 범위는 `MIN..MAX`, `MIN..`, `..MAX`, 양 끝 포함. 같은 지표의 신·구 표기 혼용과 새 옵션 반복을 거부한다. 기존 경계 옵션에 새 범위의 엄격한 숫자 문법을 확대하지 않는다.
- 사용자 조건·legacy solvers 전환 안내, 정렬 키/방향·random+desc 거부, limit/count 기본값·양수 검증을 유지한다.
- `list`는 전체 적격 후보를 정렬한 뒤 기본 20개를 표시한다. `recommend`는 전체 적격 집합에서 중복 없이 기본 1개를 추출한다.
- 사이트 검색 티어 범위와 표시 티어 차이를 유지한다. 미정·미확인·실제 0, 첫 실패 기준 고유 제외 수와 양방향 미확인 정렬 정책을 유지한다.
- 통계·문제 URL·공개 DOM 파싱의 기존 오류를 정상 미제공이나 0으로 변환하지 않는다.

## 도움말과 표시

- 루트 help는 새 명령·세 명령·플랫폼 위치·기본값·실제 선택 가능 목록을 안내한다.
- `algo-pick --platform jungol list --help`와 `recommend --help`는 정올의 지원 필터·허용 값·조합 제한을 표시한다. 공통 옵션 문법과 플랫폼별 의미를 구분한다.
- 합성 플랫폼 help에는 그 플랫폼의 규칙만 실제 지원 규칙으로 안내한다. 존재하는 공통 옵션이라도 미지원 여부를 확인할 수 있어야 한다.
- help/version은 소스 팩터리를 호출하지 않는다. 지원 표를 출력하려고 브라우저나 데이터를 요구하지 않는다.
- 지원하지 않는 속성의 열은 생략한다. 지원 속성의 개별 값 미제공만 `미확인`으로 표시한다. 정올의 기존 열·정밀도·주의 문구는 보존한다.

## open

1. 선택 플랫폼의 순수 규칙으로 ID 전체를 검증한다. 정올은 양의 정수다.
2. 유효한 고유 ID의 링크를 입력 순서대로 생성한다. ID 중복은 한 번만 전달한다.
3. 모든 링크를 stdout에 출력하고 기본 브라우저에 전달한다. 조회용 source factory는 호출하지 않는다.
4. 일부 전달 실패에도 모든 고유 링크를 시도하고 실패 번호를 stderr에 알려 코드 1로 종료한다. 전달 성공은 페이지 존재/로딩 완료 보장이 아니다.

## 스트림과 종료 코드

| 코드 | 의미 |
| --- | --- |
| 0 | 정상 결과·빈 결과·추천 부족·help/version·브라우저 전달 성공 |
| 1 | 데이터 접근·식별·구조·완전성·브라우저 전달 실패 또는 영향받은 내부 플랫폼 구성 오류 |
| 2 | 플랫폼 선택·미지원 필터·값/조합·기본 문법·개수 등 입력 오류 |
| 130 | 기존 수집 흐름의 Ctrl+C 취소 |

결과·조건·개수·시각·링크는 stdout, 진행·고유 제외 수·오류는 stderr다. 수집 실패/취소는 부분 후보를 정상 결과로 표시하지 않으며 컨텍스트를 정리한다.

## 현재 사용 자료의 변경

README, docs/integration.md, docs/standalone.md, examples/vscode/tasks.json과 export_tool 도움말의 실행 이름을 함께 바꾼다. 새 예시 폴더는 `tools/algo-pick`으로 일관되게 안내하고 VS Code input ID와 참조를 함께 맞춘다. 폴더 이름은 사용자가 지정할 수 있으며 기존 외부 복사본 폴더를 자동 이동하지 않는다. 과거 specs·검증 이력·임시 벤치 prefix의 명칭까지 전부 치환할 필요는 없다.
