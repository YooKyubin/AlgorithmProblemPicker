# Feature Specification: algo-pick 플랫폼 선택과 지원 필터 검증

**Feature Branch**: `005-platform-filter-validation`

**Created**: 2026-10-30

**Status**: Draft

**Input**: User description: "단일 CLI에서 플랫폼을 선택하고 플랫폼별 지원 필터와 값을 검증한다. 명령 이름은 jpick 대신 algo-pick으로 변경한다. 정올의 기존 동작과 개별 문제의 미제공 값 처리를 보존하며, 프로그래머스 실제 수집기는 별도 범위로 둔다."

사용자는 `algo-pick --platform jungol list`처럼 플랫폼을 선택하고, 같은 진입점에서 조회·추천·문제 열기를 실행한다.
`--platform`을 생략하면 정올을 사용한다. 각 플랫폼의 속성과 필터 값은 해당 플랫폼의 의미를 따르며, 지원하지 않는 조건은 접속 전에 입력 오류로 알린다.
이번 범위에서 실제 제공하는 플랫폼은 정올 하나다. 확장에 필요한 지원 정보와 연결 구조를 마련하되, 프로그래머스 지원을 제공한다고 표시하지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - algo-pick에서 정올을 기본으로 사용하기 (Priority: P1)

사용자는 새 명령 이름으로 기존 조회·추천·열기를 실행하고, 필요하면 정올을 명시적으로 선택한다.

**Why this priority**: 플랫폼 선택을 추가해도 기존 사용자가 얻던 정올 결과와 문제 링크를 유지하는 것이 기본 가치다.

**Independent Test**: 동일한 고정 문제 목록에서 플랫폼 생략과 `--platform jungol`의 세 명령을 비교한다. 조회는 결과·순서·개수·조건을, 추천은 후보 집합·개수·중복 여부를, 열기는 전달 URL을 확인한다.

**Acceptance Scenarios**:

1. **Given** 동일한 정올 관측 목록이 있고, **When** `algo-pick list`와 `algo-pick --platform jungol list`를 실행하면, **Then** 같은 정올 조건·결과·정렬·집계를 얻는다.
2. **Given** 같은 정올 후보와 조건이 있고, **When** 플랫폼 생략 또는 정올 명시로 `recommend --count 3`을 실행하면, **Then** 같은 적격 집합에서 중복 없이 요청 개수 이내로 추천하고 기존 부족 안내를 유지한다. 무작위 선택 결과 자체의 일치는 요구하지 않는다.
3. **Given** 문제 번호 `1000 1000 1001`이 있고, **When** 플랫폼 생략 또는 정올 명시로 `open`에 전달하면, **Then** 정올의 두 고유 문제 URL을 기본 브라우저에 전달하고 기존 실패 처리와 종료 코드를 유지한다.
4. **Given** 사용자가 설치 또는 사용법을 확인하고, **When** `algo-pick --help`, `algo-pick --version` 및 세 명령의 도움말을 실행하면, **Then** 정상 동작하며 새 명령 이름, 플랫폼 선택 위치, 기본 플랫폼과 현재 선택 가능한 플랫폼을 확인할 수 있다.

### User Story 2 - 미지원 플랫폼과 필터를 접속 전에 확인하기 (Priority: P1)

사용자는 잘못된 플랫폼이나 해당 플랫폼이 제공하지 않는 필터를 지정했을 때 어느 입력을 수정해야 하는지 즉시 확인한다.

**Why this priority**: 입력한 조건이 조용히 사라지면 의도와 다른 문제를 조회하거나 추천받게 된다. 불필요한 사이트 접근도 방지해야 한다.

**Independent Test**: 정올과 지원 필터가 다른 검증용 플랫폼을 사용해 미지원 필터를 전달하고, 사이트 접속·수집·사용자 조회·브라우저 전달이 모두 0회인 상태에서 오류를 확인한다. 검증용 플랫폼은 실제 사용자용 지원 플랫폼으로 노출하지 않는다.

**Acceptance Scenarios**:

1. **Given** 등록되지 않은 플랫폼 이름이 있고, **When** `algo-pick --platform unknown list`를 실행하면, **Then** 해당 이름과 선택 가능한 플랫폼을 안내하고 종료 코드 2로 중단한다. 정올로 대신 실행하지 않는다.
2. **Given** 검증용 플랫폼이 정답 제출 수 필터를 지원하지 않고, **When** `list` 또는 `recommend`에 `--accepted 0..0`, `--min-accepted 0`, `--max-accepted 100` 중 하나를 지정하면, **Then** 플랫폼 이름과 사용한 미지원 옵션 이름을 stderr에 안내하고 접속·수집 전에 코드 2로 중단한다.
3. **Given** 한 플랫폼이 티어와 정답률 필터를 모두 지원하지 않고, **When** 두 속성의 필터를 함께 지정하면, **Then** 지정한 미지원 필터를 모두 식별할 수 있는 오류를 출력하고 결과를 생성하지 않는다.
4. **Given** 검증용 플랫폼이 사용자 풀이 조건을 지원하지 않고, **When** `--status all`을 명시하거나 `--status solved --user someone`을 지정하면, **Then** 명시한 미지원 옵션을 거부한다. 해당 옵션을 모두 생략한 기본 실행은 풀이 필터 요청으로 간주하지 않는다.
5. **Given** 이번 릴리스에 정올만 제공되고, **When** `--platform programmers`로 세 명령 중 하나를 실행하면, **Then** 현재 선택할 수 없는 플랫폼임을 알리고 코드 2로 중단한다. 수집이나 문제 링크 열기를 시도하지 않는다.

### User Story 3 - 선택한 플랫폼의 의미에 맞게 조건 입력하기 (Priority: P1)

사용자는 같은 CLI 옵션이라도 선택한 플랫폼이 정의한 의미와 허용 값에 맞춰 사용하고, 도움말에서 지원 여부와 입력 규칙을 확인한다.

**Why this priority**: 플랫폼마다 다른 난이도·통계·사용자 조건을 정올 기준으로 해석하면 유효한 입력을 거부하거나 서로 다른 지표를 같은 뜻으로 오해하게 만든다.

**Independent Test**: 정올의 기존 유효·무효 입력과, 같은 속성에 다른 허용 값 또는 의미를 갖는 검증용 플랫폼의 입력을 각각 확인한다. 외부 사이트 접속 없이 지원 정보와 검증 결과를 비교한다.

**Acceptance Scenarios**:

1. **Given** 정올을 선택했고, **When** `list --tier S2..G3 --rate 40.5..80 --accepted 500..1000`을 실행하면, **Then** 현재 정올의 의미·경계 포함·수치 정밀도·혼용 제한을 그대로 적용한다.
2. **Given** 정올을 선택했고, **When** 역전 범위, 정답률 100 초과, 범위 옵션 반복 또는 같은 지표의 신·구 옵션 혼용을 지정하면, **Then** 기존 입력 오류와 동일하게 접속 전에 코드 2로 중단한다.
3. **Given** 검증용 플랫폼의 난이도 허용 값과 범위가 정올과 다르고, **When** 그 플랫폼에서만 유효한 난이도를 입력하면, **Then** 정올 티어 규칙 때문에 거부하지 않는다. 해당 플랫폼에서 무효인 값은 플랫폼 이름·옵션·이유와 함께 코드 2로 거부한다.
4. **Given** 두 플랫폼에서 비슷한 이름의 통계 의미가 다르고, **When** 조건 설명과 결과를 확인하면, **Then** 선택한 플랫폼의 의미·단위를 확인할 수 있다. 정답 제출 수를 맞힌 사람 수로 대신 해석하거나 없는 값을 다른 지표로 계산하지 않는다.
5. **Given** 선택한 플랫폼의 도움말을 열고, **When** `algo-pick --platform jungol list --help` 또는 `recommend --help`를 확인하면, **Then** 정올이 지원하는 필터·허용 값·상호 의존 조건을 확인할 수 있다. 향후 다른 플랫폼도 해당 플랫폼의 지원 정보를 확인할 수 있어야 한다.

### User Story 4 - 속성 미지원과 개별 값 미제공을 구분하기 (Priority: P1)

사용자는 지원하는 속성의 값이 없는 문제도 필요한 조건에 따라 조회하고, 실제 0과 미제공을 구분한다.

**Why this priority**: 플랫폼 확장 때문에 정상 후보가 사라지거나 없는 값이 0으로 해석되는 회귀를 방지한다.

**Independent Test**: 정올의 실제 0·양수·미제공 통계 및 미정·미확인 티어를 가진 고정 목록에 필터 유무를 조합해 후보·표시·제외 수와 정상 빈 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 정올 문제의 정답 제출 수가 미제공이고 다른 조건은 만족하며, **When** 해당 속성 필터 없이 조회하거나 추천하면, **Then** 후보에 포함하고 해당 값을 `미확인`으로 표시한다.
2. **Given** 정답 제출 수가 미제공·0·10인 문제가 있고, **When** `--accepted 0..0`을 지정하면, **Then** 실제 0인 문제만 적격이며 미제공 문제는 기존 제외 수에 반영한다. 정답률의 실제 0과 미제공도 같은 원칙을 따른다.
3. **Given** 한 문제의 여러 필터 대상 값이 미제공이거나 수집 목록에 같은 문제가 반복되고, **When** 해당 필터를 적용하면, **Then** 기존처럼 고유 문제당 한 번 제외 개수를 알린다.
4. **Given** 유효한 조건으로 적격 문제가 0개이거나 요청 추천 수보다 적고, **When** 조회 또는 추천을 완료하면, **Then** 기존 빈 결과·부족 안내와 종료 코드 0을 유지한다.
5. **Given** 플랫폼 자체가 어떤 속성을 지원하지 않고 사용자가 그 필터를 생략했으며, **When** 결과를 확인하면, **Then** 그 속성의 부재 때문에 문제를 제외하거나 제외 개수를 늘리지 않는다. 해당 속성을 개별 문제의 `미확인` 값으로 표시하지 않고 결과 열에서 생략한다.
6. **Given** 정올의 티어 검색 결과에 요청 범위 밖 확정 티어와 미정·미확인 티어가 있고, **When** 티어 조건을 적용하면, **Then** 기존처럼 범위 밖 확정 티어를 보존하고 미정·미확인 티어의 필터·표시 정책을 유지한다.

### User Story 5 - 공통 사용 흐름을 유지하며 플랫폼 연결하기 (Priority: P2)

유지보수자는 각 플랫폼의 지원 정보와 수집 방식을 연결해 같은 조회·추천·열기 사용법을 확장한다.

**Why this priority**: 새로운 플랫폼마다 명령과 추천 동작이 달라지면 사용자 경험과 유지보수 비용이 함께 악화된다.

**Independent Test**: 실제 사이트에 접속하지 않는 검증용 플랫폼 하나를 연결해 정올과 다른 지원 속성·값·문제 링크를 제공하고, 동일한 세 명령의 사용 흐름으로 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 정올과 지원 필터·난이도 값·문제 URL이 다른 검증용 플랫폼이 연결되어 있고, **When** 그 플랫폼에서 `list`, `recommend`, `open`을 실행하면, **Then** 해당 플랫폼의 데이터·규칙·링크를 사용하며 정올 수집이나 정올 링크를 대신 사용하지 않는다.
2. **Given** 검증용 플랫폼을 추가하고, **When** 지원 정보와 수집·문제 열기 연결을 구성하면, **Then** 공통 CLI 명령과 추천 흐름을 플랫폼별로 복제하지 않고 세 명령을 제공할 수 있다.
3. **Given** 같은 번호를 가진 문제가 정올과 검증용 플랫폼에 각각 있고, **When** 선택한 플랫폼에서 문제를 열면, **Then** 그 플랫폼의 문제 링크만 전달한다.

### Edge Cases

- 플랫폼 옵션은 공통 옵션으로 명령 앞에 지정한다. 기준 사용법은 `algo-pick --platform jungol list`이며 명령 뒤의 중복 표기나 별칭은 이번 범위에서 추가하지 않는다.
- 플랫폼을 생략한 경우만 정올을 기본 선택한다. 빈 문자열·오타·미등록 이름은 기본값으로 보정하지 않고 코드 2로 거부한다.
- 플랫폼 식별자는 이번 범위에서 소문자 `jungol`을 사용한다. 한국어 이름·대소문자 변형·약칭을 자동으로 같은 선택으로 간주하지 않는다.
- 미지원 필터는 값이 0이거나 명시한 값이 기본값과 같아도 거부한다. 생략된 기본값은 명시적인 필터 요청과 구분한다.
- 범위 표기와 기존 `--min-*`·`--max-*` 표기는 같은 속성의 지원 여부를 따르며, 어느 표기로도 미지원 검증을 우회할 수 없다.
- 미지원 옵션의 값까지 잘못된 경우에도 플랫폼의 미지원 필터라는 사실과 해당 옵션을 확인할 수 있어야 한다. 지원 여부는 해당 플랫폼의 값 해석보다 먼저 판단한다.
- 지원하는 필터의 값·조합 오류도 사이트 접속, 수집 및 사용자 조회를 시작하기 전에 실패해야 한다.
- 검증용 플랫폼은 합성 지원 정보이며 프로그래머스의 실제 제공 속성·자동 접근 허가를 주장하는 근거로 사용하지 않는다.
- 정올의 셀 누락·중복·잘못된 숫자·해석 불가능한 표시를 미제공이나 0으로 바꾸지 않는 기존 오류 정책을 유지한다.
- 미정·미확인 값의 정렬상 위치, 동점 정렬, 전체 후보 처리 후 표시 제한, 추천 중복 제거 및 빈 결과 처리는 플랫폼 선택 추가로 바꾸지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 설치 후 실행하는 기본 명령 이름을 `jpick`에서 `algo-pick`으로 변경해야 한다. 도움말·오류 사용법·README·통합 가이드·배포 및 실행 예제의 현재 사용법을 새 이름으로 안내해야 한다. 과거 명세·검증 이력의 명령 표기는 변경할 필요가 없다.
- **FR-002**: 공통 옵션 `--platform`으로 `list`, `recommend`, `open`의 대상 플랫폼을 선택해야 한다. 생략 시 `jungol`을 사용하고, 명시한 미등록 이름을 정올로 대체해서는 안 된다.
- **FR-003**: 이번 릴리스의 실제 선택 가능한 플랫폼은 `jungol`이어야 한다. 미등록·빈 플랫폼 이름은 이름과 선택 가능한 값 안내 후 종료 코드 2로 거부해야 하며 외부 작업을 시작해서는 안 된다.
- **FR-004**: 세 명령은 선택한 플랫폼의 문제·속성 의미·식별자·링크를 사용해야 한다. `open`은 기존처럼 직접 지정한 문제의 링크를 전달하며 조회·추천을 선행하지 않아야 한다.
- **FR-005**: 각 플랫폼은 지원 필터, 필터별 대상 속성의 의미·단위, 허용 값·범위·표기 및 필터 조합 제약을 명시적으로 정의해야 한다. 다른 플랫폼의 규칙을 일괄 적용하거나 유사한 속성으로 대체해서는 안 된다.
- **FR-006**: `list`와 `recommend`는 사용자가 명시한 모든 필터의 지원 여부를 선택한 플랫폼 기준으로 검사해야 한다. 미지원 필터를 무시하거나 기본값으로 대체해서는 안 되며, 범위 옵션·기존 경계 옵션·사용자 조건에도 동일하게 적용해야 한다.
- **FR-007**: 미지원 필터가 하나 이상이면 플랫폼 이름과 지정한 모든 미지원 옵션 이름을 stderr에 출력하고 코드 2로 중단해야 한다. 사이트 접속·수집·사용자 조회·기본 브라우저 전달 횟수는 모두 0이어야 하며 부분 결과를 출력해서는 안 된다.
- **FR-008**: 필터 지원 여부는 그 플랫폼의 필터 값 해석 전에 판단해야 한다. 지원하는 필터의 값·조합도 해당 플랫폼 규칙으로 외부 작업 전에 검증하고, 무효이면 플랫폼 이름·옵션·수정 이유와 함께 코드 2로 거부해야 한다.
- **FR-009**: 필터 생략과 명시적 기본값을 구분해야 한다. 예를 들어 사용자 풀이 조건 미지원 플랫폼에서 생략된 `--status` 기본값은 요청으로 취급하지 않지만 명시한 `--status all`은 미지원 입력으로 거부해야 한다.
- **FR-010**: 정올은 아래 지원 필터 표와 현재 실행 기준의 규칙을 유지해야 한다. 플랫폼 선택·명령 이름 변경 외에는 기존 정올의 범위 표기, 경계 포함, 입력 정밀도, 신·구 표기 혼용 금지, 반복 금지 및 사용자 조건 의미를 바꾸지 않아야 한다.
- **FR-011**: 플랫폼 자체의 속성 미지원과 지원 속성의 개별 문제 값 미제공을 구분해야 한다. 미지원 속성은 해당 필터 없이 실행할 때 후보 제외·미제공 제외 집계를 유발하지 않으며 결과 열에서 생략해야 한다.
- **FR-012**: 정올의 지원 속성이 개별 문제에서 미제공이면 해당 필터가 있을 때 제외하고, 없으면 다른 조건을 만족하는 문제를 포함해 `미확인`으로 표시해야 한다. 실제 숫자 0을 미제공과 구분하고, 미제공 문제의 제외 개수는 기존처럼 고유 문제당 한 번 집계해야 한다.
- **FR-013**: 정올의 티어 검색 조건과 표시 티어의 차이, 범위 밖 확정 티어 보존, 미정·미확인 티어 처리, 정렬·동점 규칙, 전체 후보 수집 후 표시 제한, 중복 없는 추천 및 수집 완료·실패 정책을 보존해야 한다.
- **FR-014**: 유효한 조건의 빈 결과·추천 부족은 종료 코드 0이어야 한다. 기존 접속·데이터·브라우저 실패 코드 1, 입력 오류 코드 2와 취소 코드 130 및 stdout/stderr 구분을 유지해야 한다.
- **FR-015**: 도움말과 현재 사용 문서는 새 명령 이름, `--platform`의 위치·기본값·선택 가능한 플랫폼, 플랫폼별 지원 필터와 값 규칙을 설명해야 한다. 플랫폼 생략·정올 명시 예시와 신규 수집기 미제공 범위를 확인할 수 있어야 한다.
- **FR-016**: 향후 플랫폼은 공통 CLI와 추천 흐름을 복제하지 않고 플랫폼별 지원 정보와 수집·문제 열기 방식을 연결해 추가할 수 있어야 한다. 이를 정올과 지원 속성·허용 값·링크가 다른 검증용 플랫폼 한 개로 확인할 수 있어야 한다.

### 정올 지원 필터 기준

| 속성 / 조건 | 지원 옵션 | 보존할 의미와 검증 기준 |
| --- | --- | --- |
| 티어 검색 조건 | `--tier`, `--min-tier`, `--max-tier` | B5~R1 약칭은 대소문자 무관, 기존 1~30 정수도 허용. 사이트 검색 조건이며 표시 티어와 다를 수 있음 |
| 정답률 | `--rate`, `--min-rate`, `--max-rate` | 0~100의 유한 정수·소수, `%` 없이 입력. 목록의 표시 정밀도를 보존하며 다른 통계로 재계산하지 않음 |
| 정답 제출 수 | `--accepted`, `--min-accepted`, `--max-accepted` | 0 이상 정수. 동일 사용자의 중복 정답 제출 포함. 맞힌 사람 수·전체 제출 수와 구분 |
| 공개 사용자 풀이 여부 | `--status`, `--user` | `all` 기본, `solved`·`unsolved`에는 정확한 공개 핸들 필요. `all + user` 거부. 선행 `@` 한 개 허용, 대소문자 보존 |

세 범위 옵션의 `MIN..MAX`, `MIN..`, `..MAX` 문법, 적어도 한 경계 필요, 양 끝 포함, 경계 역전 금지, 같은 지표의 범위·경계 옵션 혼용 및 범위 옵션 반복 거부를 유지한다.
정올의 기존 `--min-solvers`, `--max-solvers`, `--sort solvers`는 계속 코드 2로 거부하고 기존 전환 안내를 제공한다.
정렬·표시 개수·추천 개수는 필터로 새로 분류하지 않으며 기존 정올의 지원 값과 조합 검증을 유지한다.

### Key Entities *(include if feature involves data)*

- **플랫폼**: 사용자가 선택하는 문제 제공처. 선택 식별자·표시 이름, 문제 조회와 링크 열기의 대상이며 이번 실제 제공처는 정올이다.
- **플랫폼별 지원 정보**: 해당 제공처가 지원하는 속성·필터와 각 값의 의미·단위·허용 범위·조합 제약. 개별 문제의 값 보유 여부와 별개다.
- **필터 요청**: 사용자가 명시한 옵션 이름과 값, 그리고 그 대상 플랫폼. 생략과 명시적 기본값을 구분하고 검증 후 조회·추천 조건으로 사용한다.
- **플랫폼별 문제**: 해당 플랫폼 안의 문제 식별자·제목·링크와 제공 속성. 다른 플랫폼의 같은 번호는 다른 문제이며 속성 의미를 강제로 통일하지 않는다.
- **속성 값 상태**: 플랫폼의 속성 미지원, 지원 속성의 개별 값 미제공, 실제 제공 값을 구분한다. 정올의 정상 미정 티어 상태와 실제 숫자 0도 기존처럼 보존한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 세 명령 각각에서 플랫폼 생략과 정올 명시의 6개 기본 실행 조합이 모두 성공한다. 고정 관측 목록 기준 조회 결과·정렬·집계와 열기 URL의 기존 정올 동작 일치율은 100%이며, 추천 후보·개수·중복 정책도 모두 일치한다.
- **SC-002**: 두 조회·추천 명령에서 미지원 필터의 범위·하한·상한·사용자 조건·명시적 기본값 사례와 복수 미지원 사례를 확인했을 때, 플랫폼 및 미지원 옵션 안내와 종료 코드 2 일치율은 100%다. 해당 실행의 외부 접속·수집·브라우저 전달은 0회다.
- **SC-003**: 세 명령의 미등록 플랫폼 입력, 정올의 기존 무효 입력, 검증용 플랫폼 고유의 유효·무효 입력 사례에서 선택한 플랫폼 기준 판정 일치율은 100%이며, 정올로 잘못 대체된 실행은 0건이다.
- **SC-004**: 실제 0·미제공·미정 티어·중복 문제·빈 결과·추천 부족 검증에서 기존 후보 포함·제외, 표시, 고유 제외 수와 종료 코드 정책 일치율은 100%다. 속성 자체 미지원 때문에 제외되거나 개별 값 `미확인`으로 잘못 표시된 문제는 0건이다.
- **SC-005**: 정올과 지원 조건·문제 링크가 다른 검증용 플랫폼 한 개를 동일한 세 명령으로 시연할 수 있다. 각 실행에서 선택하지 않은 플랫폼의 수집이나 링크 전달은 0회이며 새 실제 사이트 수집기 없이 확인할 수 있다.
- **SC-006**: 사용자는 도움말과 현재 사용 문서만으로 기본 정올 조회, 정올 명시 추천, 정올 문제 열기의 3개 예시를 실행할 수 있고, 각 필터의 지원 여부·의미·허용 값을 확인할 수 있다. 현재 사용 예시에서 `jpick` 실행을 요구하거나 프로그래머스가 제공된다고 안내하는 상충 항목은 0개다.

## Assumptions

- 첫 항목의 `jpick` 유지 문구는 후속 문장인 “jpick 대신 algo-pick으로 이름 변경”으로 대체된 것으로 해석한다. 기본 실행 이름은 `algo-pick`이며 `jpick` 호환 별칭 제공은 이번 요구에 포함하지 않는다. 배포 패키지 이름이나 내부 모듈 이름까지 변경하라는 요구로 확대하지 않는다.
- 플랫폼 선택은 한 실행에 한 개다. 플랫폼 통합 검색·교차 추천·여러 플랫폼 결과 합치기·플랫폼 자동 감지는 범위 밖이다.
- 프로그래머스는 확장 동기를 설명하는 예시다. 실제 수집기·인증·URL 규칙·필터 목록을 이번에 구현하거나 사실로 확정하지 않는다. 실제 지원 추가는 접근 허가와 제공 속성 확인을 포함한 별도 요구로 다룬다.
- 검증용 플랫폼은 확장과 미지원 조건 처리를 확인하기 위한 합성 사례다. 실제 사이트·계정에 의존하지 않으며 일반 도움말의 선택 가능 목록에는 노출하지 않는다.
- 현재 실행 기준은 [README](../../README.md), [003 명세](../003-align-site-listing/spec.md), [004 명세](../004-add-range-options/spec.md)와 현재 코드에서 확인한 티어 약칭 지원이다. 선행 명세의 숫자 전용 예시를 근거로 현재 약칭 입력을 제거하지 않는다.
- 정올의 비영구 수집·공개 화면 접근·접속 제한·수집 종료 정책에 의존한다. 플랫폼 선택을 이유로 영구 캐시·오프라인 조회·새 접근 방식·재시도를 추가하지 않는다.
- 현재 [헌장](../../.specify/memory/constitution.md) I의 “프로그래머스 지원과 플랫폼 통합 제외”는 이번 플랫폼 선택·확장 요구와 충돌한다. 이번 사용자 요구를 우선하며 계획 단계에서 해당 원칙의 범위 조정과 변경 영향을 명시적으로 정합화해야 한다. 헌장 III의 로컬 캐시 원칙과 선행 합의한 비영구 처리의 차이도 함께 기록해야 한다. 이 명세 작성 단계에서는 헌장 자체를 수정하지 않는다.
- 이번 명령의 산출물은 명세·품질 체크리스트·활성 기능 경로다. 제품 코드·배포 설정·사용 문서 변경과 실행 검증은 후속 계획·구현 단계에서 수행한다.
