# JUNGOL 데이터 접근·URL 필터 조사

조사일: 2026-10-19. 공개 페이지·공개 클라이언트 확인 결과이며, 구현 설계는 계획 단계에서 확정한다.

## 결론

- 정올 웹사이트가 사용하는 내부 API는 존재한다.
- 외부 개발자용 공개 API 문서, 사용 계약, 안정적인 공개 JSON 응답은 이번 조사에서 확인하지 못했다.
  공개 API가 없다고 단정하는 것은 아니다.
- 난이도·풀이 사용자·일부 푼 사람 수 조건과 정렬은 URL로 표현된다.
  정답률 범위·정렬, 임의의 푼 사람 수 범위, 무작위 기능은 별도 처리가 필요하다.
- 권장 방향은 지원되는 조건으로 후보를 좁힌 뒤 전체 후보에 나머지 조건·정렬·추첨을 적용하는 것이다.
  문제 목록의 영구 저장은 이번 범위에 포함하지 않는다.

## API 확인 결과

| 확인 항목 | 근거와 한계 |
| --- | --- |
| API 서버 존재 | [공식 변경 이력](https://jungol.co.kr/about/whatsnew?lang=ko)에 API 서버 업데이트 기록이 있다. |
| 현재 클라이언트의 API 주소 | [공개 API 모듈](https://jungol.co.kr/_app/immutable/chunks/CMlQ6Drv.js)에 `https://api.jungol.co.kr`와 같은 출처의 `/api` 프록시 선택 코드가 있다. |
| 일반 공개 JSON 형태 여부 | 위 모듈은 `X-Fp`·`X-Api` 헤더와 `application/octet-stream`을 사용하며, 응답을 바이너리로 읽어 별도 해석한다. 단순 JSON 호출을 전제할 수 없다. |
| 직접 조회 시험 | `https://api.jungol.co.kr/problem`에 읽기 전용 요청 한 번을 보냈으나 HTTP 200 HTML이 반환됐다. 문제 목록 데이터 응답으로 확인되지 않았다. |
| 문제 목록과 조회 방식 | [문제 목록 모듈](https://jungol.co.kr/_app/immutable/chunks/6tH2-dSg.js)은 문제 조회에 페이지 방식과 커서 방식을 구분한다. 단순 `page` 증가만으로 모든 필터 결과를 가져올 수 있다고 가정하면 안 된다. |
| 공개 API 지원 정책 | 홈페이지와 공개 검색에서 외부 개발자용 문서를 찾지 못했다. 내부 호출 형식 관찰은 외부 사용 허가의 근거가 아니다. |

위 정적 파일 이름은 배포마다 바뀔 수 있다. 현재 파일 주소를 안정적인 연동 계약으로 사용하지 않는다.

## URL로 처리되는 기능과 별도 처리할 기능

[문제은행](https://jungol.co.kr/problem)의 필터 UI와
[공개 검색 화면 모듈](https://jungol.co.kr/_app/immutable/nodes/132.Dwz0Xjuo.js)을 확인했다.

| 기능 | 확인된 URL 표현 | 권장 처리·검증 범위 |
| --- | --- | --- |
| 난이도 범위 | `minTier`, `maxTier` | UI에서 슬라이더 조작으로 값과 URL 변경을 확인했다. 티어 1~30이며 `unrated` 정책도 함께 고려한다. |
| 난이도 미정 | `unrated=include/exclude/only` | UI에 포함·제외·언랭만이 있다. 하한을 1보다 높이면 제외가 자동 적용되는 것을 확인했다. |
| 난이도 정렬 | `sort=tierAsc/tierDesc` | UI에서 양방향 선택과 URL 변경을 확인했다. 선택 시 `unrated=exclude`도 자동 적용된다. |
| 푼 사람 수 정렬 | `sort=solvedAsc/solvedDesc` | UI에서 양방향 선택과 URL 변경을 확인했다. |
| 제한된 푼 사람 수 필터 | `solverCount=zero/gte10` | 화면에는 전체·0명·10명 이상이 있다. 10명 이상 선택으로 `gte10` URL을 확인했다. |
| 임의의 푼 사람 수 범위 | 화면에 임의 상·하한 없음 | 예: 50~500명은 전체 후보의 실제 푼 사람 수로 추가 필터링한다. 제공되지 않는 URL 매개변수를 만들어 지원된다고 가정하지 않는다. |
| 지정 사용자의 풀이 여부 | `solvedBy=<사용자 숫자 ID>`, `solvedByMode=include/exclude` | 비로그인 공개 사용자 검색·선택으로 `include` URL을 확인했다. `exclude`는 공개 클라이언트에서 확인했으며 실제 미풀이 결과는 추가 검증한다. |
| 로그인 사용자 풀이 상태 | `status=solved/unsolved` | 공개 클라이언트에 존재한다. 이번 기능은 사용자가 선택한 공개 사용자 기준을 사용하므로 로그인 기능을 요구하지 않는다. |
| 정답률 범위·정렬 | 대응하는 화면 필터·정렬 없음 | 정답률을 읽어 별도 범위 필터·정렬을 수행하는 것을 추천한다. 미공개 매개변수 지원 여부는 확인되지 않았다. |
| 무작위순·N개 추천 | 대응하는 화면 정렬·추첨 없음 | 모든 적격 후보를 대상으로 중복 없는 무작위 선택을 수행한다. 첫 페이지나 임의 한 페이지만으로 추첨하지 않는다. |
| 문제 열기 | `/problem/<문제 번호>` | 결과의 실제 문제 링크를 기본 브라우저에서 연다. |

예: [난이도·푼 사람 수 조건을 조합한 문제은행](https://jungol.co.kr/problem?sort=solvedDesc&minTier=2&maxTier=29&unrated=exclude&solverCount=gte10)

URL은 조회 조건의 표현이다. 해당 URL이 있다고 해서 정답률이나 임의의 완료자 수 조건까지
서버에서 처리된다고 가정하지 않는다. 사용자 이름을 숫자 ID로 해석하는 과정도 필요하다.

정올 UI의 난이도 정렬은 난이도 미정 문제를 자동으로 제외한다. 이번 명세는 범위 필터가 없으면
미정 문제도 포함하고 정렬의 마지막에 둔다. 따라서 서버 정렬을 그대로 사용해 미정 문제를
누락시키지 말고, 후보 조회와 최종 정렬을 구분해 명세의 포함 정책을 보장해야 한다.

## 지표 의미와 데이터 확보 주의점

- 사용자가 완료자 수를 중복 제출을 제외한 **푼 사람 수**로 확정했다.
- [문제 표시 모듈](https://jungol.co.kr/_app/immutable/chunks/Bi6QUMYJ.js)은
  정답률을 정답 제출 수와 전체 제출 수의 비율로 표시한다.
  푼 사람 수를 정답률 계산에 사용하지 않는다.
- 실제 [1000번 문제](https://jungol.co.kr/problem/1000) 화면에서 전체 제출 13,720,
  정답 제출 6,510, 사람 수 5,171이 각각 별도로 표시되는 것을 확인했다.
  수치는 조사 시점 기준이며 변할 수 있다.
- 좁은 화면의 목록에서 정답률 옆에 보이는 정수는 전체 제출 수다.
  이를 푼 사람 수로 읽으면 완료자 수 필터가 잘못된다.
- 목록 데이터에서 실제 푼 사람 수를 얻을 수 있는지와 그 필드 의미는 계획 단계에서 검증한다.
  추가 상세 조회가 필요하면 요청 수·진행 안내를 고려하되, 제출 수로 대체하지 않는다.
- 난이도·정답률·풀이 상태는 확인 불가와 0·미풀이를 구분한다.

## 접근 허용 여부와 남은 확인

[robots.txt](https://jungol.co.kr/robots.txt)는 일반 에이전트에 `Allow: /`를 제공하지만,
학습 크롤러별 제한과 용도별 신호도 포함한다. 이것만으로 모든 자동 이용의 허가를 판단하지 않는다.
[이용약관](https://jungol.co.kr/about/provision)도 확인했으나, 이번 조사로 외부 프로그램의
문제 목록 자동 수집과 API 직접 사용에 대한 명시적 허가를 확보한 것은 아니다.

계획 단계에서 다음을 확인한다.

1. 사용할 자동 접근 방식의 허용 근거와 외부 API 지원 정책.
2. 전체 후보를 끝까지 조회하는 방법과 페이지·커서 종료 조건.
3. 목록 또는 상세 정보에서 푼 사람 수·티어·정답률을 정확하게 얻는 방법.
4. 지정 사용자 이름의 정확한 식별과 푼 문제 포함·제외 결과의 실제 일치 여부.

공식 공개 API가 확인되면 우선 검토하고, 그렇지 않으면 허용된 공개 화면 기반 조회를 검토한다.
방식과 무관하게 명세의 필터·정렬·추천 의미를 동일하게 유지한다.
