# JUNGOL Source Contract

아래는 외부 사이트와 도메인을 분리하는 내부 경계다.
사용자 공개 인터페이스는 [CLI 계약](cli.md)을 따른다.
내부 API 엔드포인트나 현재 해시가 붙은 JS 파일은 구현 계약으로 삼지 않는다.

## 최소 경계

- `resolve_user(handle) → UserReference`: 사이트의 공개 사용자 선택 UI로 정확한 핸들을 해석.
- `collect(criteria, user) → CompletedListing`: 일반 문제 목록을 끝까지 읽어 고유 후보 반환.
- `read_details(candidate) → Problem`: 같은 문제 상세의 공개 푼 사람 수만 읽어 보강.

브라우저 수명은 공급자가 관리한다. 인터페이스는 typing.Protocol 하나로 표현하고,
이 경계 밖에서는 Playwright·DOM 로케이터·정올 URL 매개변수를 참조하지 않는다.
테스트만을 위한 공개 함수나 별도 공급자 프레임워크를 만들지 않는다.

## 공개 화면 탐색

- origin은 정올 HTTPS로 고정하고 한국어 페이지와 1280×900 뷰포트를 사용한다.
- 항상 일반 문제만 조회한다. type=problem과 번호 오름차순을 사용한다.
- minTier·maxTier는 지정된 경우에만 전달하고, 티어 범위가 있으면 unrated=exclude다.
  범위가 없으면 unrated=include를 유지하며 서버 난이도 정렬은 쓰지 않는다.
- 사용자 조건은 사이트에서 확인한 account_id와 solvedByMode=include/exclude로 적용한다.
  status=solved/unsolved나 로그인 상태는 사용하지 않는다.
- 정답률·임의의 푼 사람 수·최종 정렬·표시 개수는 로컬 처리다.
  첫 구현에서는 solverCount=zero/gte10 최적화도 생략해 경로를 단순하게 유지한다.
- 새 컨텍스트 한 개, 목록·상세용 페이지 각 한 개를 사용하고 데이터 탐색은 순차 수행한다.
  탐색 또는 더 불러오기 시작 사이를 최소 1초 간격으로 제한한다.
- 사이트가 자체적으로 수행하는 요청만 사용한다. 별도 API 호출·응답 디코딩·내부 상태 읽기는 하지 않는다.

## DOM 추출과 완료 판정

목록의 의미 있는 헤더·문제 링크로 행 범위를 정하고 다음을 읽는다.

| 항목 | 추출 계약 |
| --- | --- |
| id·url | 해당 행의 정올 /problem/<ID> 링크 |
| title | 문제 제목 링크의 보이는 텍스트 |
| tier | 해당 문제의 /solved/<1~30>.svg 배지 또는 검증된 미정 표현 |
| pass_rate | 정답률 열 또는 해당 행의 퍼센트 표시. Decimal로 파싱 |
| solver_count | 상세의 title='맞힌 사람' 통계. 쉼표를 제거한 정수 |

해시 CSS 클래스와 전체 화면의 첫 숫자·색상·고정 열 번호에 의존하지 않는다.
상세의 제출·정답·맞힌 사람 통계가 섞이지 않도록 문제 헤더 범위에서 의미를 식별한다.
상세 문제 번호가 후보와 일치하는지 확인한다. 최종 Problem의 티어·정답률은 목록에서
관측한 값을 유지하고 상세 값으로 덮어쓰지 않는다. 따라서 사전 필터와 최종 표시 값이 일치한다.
필수 요소의 중복·누락이나 알 수 없는 티어 배지는 SourceSchemaError다.
검증된 미정 표현과 명시적인 빈 지표만 정상 부재로 처리한다.

번호 페이지는 실제 다음 페이지 링크를 따른다.
커서 목록은 더 불러오기 버튼으로 진행하고, 누적 DOM 전체에서 새 ID를 합친다.
domcontentloaded와 정상 결과·명시적인 빈 상태·오류 상태를 구분하는 준비 조건을 사용한다.
추가 동작 후에는 로딩 종료와 새 ID·최종 종료·오류를 함께 확인한다.
같은 URL·같은 ID만 반복되거나 버튼이 계속 남은 채 진행이 없으면 실패한다.
로드 중 DOM이 비어 있거나 버튼이 잠깐 사라진 상태는 종료가 아니다.

## 오류와 수명

- 기본 탐색 제한은 30초, DOM 준비·동작 제한은 15초다.
- navigation 응답의 HTTP 실패 상태는 직접 확인한다.
  403·429, 로그인 요구·챌린지, 필터 미적용은 접근 실패다.
- 사용자 없음·모호함, 전송 실패, 구조 변경, 반복 페이지를 구분해 원인을 전파한다.
  빈 목록·미확인 지표로 바꾸지 않으며 자동 재시도하지 않는다.
- Ctrl+C·예외·정상 종료 모두에서 context와 browser를 닫는다.
- 사용자 ID·후보·통계는 실행 중에만 보유한다. 프로필·storage_state·HAR·추적 파일을 저장하지 않는다.
