# Feature Specification: 안정적인 티어 수집과 정답 제출 수 기반 조회·추천

**Feature Branch**: `002-improve-list-collection`

**Created**: 2026-10-20

**Status**: Draft

**Input**: [001 구현 이후 테스트 이슈](../001-jungol-problem-picker/post-implementation-issues.md)의 ISSUE-001(티어 미정·미확인 문제로 인한 수집 중단)과 ISSUE-002(solver 수집을 위한 문제별 상세 조회로 인한 지연)를 해결하는 002 기능을 정의한다.

이번 기능은 티어 범위에서 정상적인 미정·미확인 문제를 제외하고 수집을 계속하며,
맞힌 사람 수 대신 목록에 표시된 정답 제출 수로 필터·정렬·출력한다.
조회·추천은 문제 상세 조회 없이 전체 목록을 확인한 뒤 수행한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 미정·미확인 티어가 섞여 있어도 조건에 맞는 문제 찾기 (Priority: P1)

사용자는 티어 범위를 지정했을 때 미정·미확인 문제가 나타나더라도,
확인 가능한 정상 후보를 끝까지 수집해 조회하거나 추천받는다.
실제 데이터 오류가 있으면 문제를 식별할 수 있는 진단을 받는다.

**Why this priority**: 현재는 미정·미확인 문제 하나가 정상 후보의 추천까지 막을 수 있다.

**Independent Test**: 첫 목록과 추가 목록에 범위 안 티어, 정상적으로 식별된 미정·미확인 티어를
섞어 조회·추천하고, 별도 사례로 범위 밖 티어와 읽을 수 없는 티어를 제공해 결과와 실패를 확인한다.

**Acceptance Scenarios**:

1. **Given** 티어 9~14와 정상적인 미정·미확인 문제가 첫 목록 및 추가 목록에 섞여 있고,
   **When** 티어 9~14로 조회하거나 추천하면,
   **Then** 미정·미확인 문제를 제외한 전체 후보를 확인하고 범위 안 문제만 반환한다.
2. **Given** 티어 하한 또는 상한만 지정했고 목록이 여러 번 추가되며,
   **When** 수집하면,
   **Then** 처음부터 끝까지 지정한 경계와 미정 문제 제외 조건이 유지된다.
3. **Given** 지정 범위 밖의 확정 티어를 가진 문제가 반환되며,
   **When** 수집하면,
   **Then** 필터 적용 이상으로 실패하고 문제 번호·읽은 티어·요청 범위를 안내하며 최종 결과를 반환하지 않는다.
4. **Given** 예상한 티어 표시 구조가 없거나 티어 표시를 해석할 수 없고,
   **When** 수집하면,
   **Then** 이를 정상적인 미확인으로 바꾸지 않고 해당 문제와 원인을 포함한 조회 실패로 안내한다.
5. **Given** 티어 범위를 지정하지 않았고 미정·미확인 문제가 있으며,
   **When** 조회하거나 난이도순으로 정렬하면,
   **Then** 해당 문제를 포함하고 상태를 구분해 표시하며 양방향 정렬 모두에서 마지막에 둔다.
6. **Given** 수집된 문제가 모두 미정·미확인이고 티어 범위를 지정했으며,
   **When** 전체 수집을 완료하면,
   **Then** 조회 실패가 아닌 정상적인 후보 0개로 안내한다.

### User Story 2 - 목록의 정답 제출 수로 상세 조회 없이 조회·추천하기 (Priority: P1)

사용자는 목록에 표시된 정답 제출 수와 난이도·정답률·지정 사용자의 풀이 여부로
문제를 찾고 추천받는다. 각 후보의 상세 통계를 확인하는 추가 대기 없이 결과를 받는다.

**Why this priority**: 적은 수의 추천을 받을 때도 후보마다 상세 조회가 발생하는 지연을 제거한다.

**Independent Test**: 정답 제출 수·전체 제출 수·맞힌 사람 수가 서로 다른 검증 자료로
필터·정렬·추천을 실행하고, 결과의 지표와 전체 후보 처리 여부 및 상세 조회 횟수를 확인한다.

**Acceptance Scenarios**:

1. **Given** 정답 제출 수가 0, 9, 10, 20, 21인 문제와 명시적 미제공 문제가 있으며,
   **When** 최소 10·최대 20으로 조회하거나 추천하면,
   **Then** 10과 20인 문제만 적격 후보가 되고 미제공 문제는 조건에서 제외된다.
2. **Given** 정답 제출 수·전체 제출 수·맞힌 사람 수가 서로 다르며,
   **When** 정답 제출 수로 필터·정렬·출력하면,
   **Then** 목록의 정답 제출 수만 사용하고 정답률은 목록 표시값을 그대로 사용한다.
3. **Given** 정답 제출 수가 같은 문제와 미제공 문제가 여러 목록에 있으며,
   **When** 정답 제출 수로 오름차순 또는 내림차순 조회하면,
   **Then** 전체 적격 후보를 정렬한 뒤 표시 개수를 제한하고 동점은 번호 오름차순,
   미제공은 방향과 관계없이 마지막에 표시한다.
4. **Given** 정답 제출 수 조건을 생략하거나 표시·추천 개수를 1로 지정했고,
   **When** 조회하거나 추천하면,
   **Then** 전체 후보를 확인하되 문제 상세 조회는 수행하지 않는다.
5. **Given** 목록에 실제 정답 제출 수 0과 명시적 미제공 값이 있고,
   **When** 해당 지표의 필터 없이 조회하면,
   **Then** 각각 0과 미확인으로 표시하고, 최소·최대 0으로 조회하면 실제 0만 포함한다.
6. **Given** 정답 제출 수 표시 구조가 없거나 수치를 해석할 수 없으며,
   **When** 수집하면,
   **Then** 0·미확인으로 대체하거나 상세 조회로 보충하지 않고 조회 실패를 안내한다.
7. **Given** 서로 다른 목록에 중복 후보와 지정 공개 사용자의 풀이 조건이 있으며,
   **When** 조건에 맞는 문제 N개를 추천하면,
   **Then** 지정 사용자 기준의 전체 고유 적격 후보에서 동일한 선택 기회로 중복 없이 선택한다.
8. **Given** 후보가 N개 미만이거나 없고 전체 수집이 정상 완료되며,
   **When** N개를 추천하면,
   **Then** 가능한 후보 전부와 실제 개수·부족 안내를 반환한다.

### User Story 3 - 바뀐 지표의 의미와 사용법 이해하기 (Priority: P2)

사용자는 도움말·출력·사용 예시에서 정답 제출 수의 의미를 확인하고 새 옵션으로 전환한다.
기존 solver 옵션으로 다른 의미의 결과를 받는 일이 없어야 한다.

**Why this priority**: 정답 제출 수와 맞힌 사람 수는 다른 지표이므로 명시적인 사용법 변경이 필요하다.

**Independent Test**: 새 옵션과 기존 옵션을 각각 실행하고 도움말·결과·전환 안내를 비교한다.
선택한 문제 열기도 별도로 확인한다.

**Acceptance Scenarios**:

1. **Given** 도움말이나 사용 예시를 확인하는 사용자,
   **When** 정답 제출 수 조건과 정렬 방법을 읽으면,
   **Then** `--min-accepted`·`--max-accepted`·`--sort accepted`를 찾고
   동일 사용자의 중복 정답 제출도 포함한다는 설명을 확인할 수 있다.
2. **Given** 기존 `--min-solvers`·`--max-solvers`·`--sort solvers` 중 하나를 사용하며,
   **When** 실행하면,
   **Then** 입력 오류로 종료하고 지표 변경 및 대응하는 새 옵션을 안내한다.
3. **Given** 조회·추천이 완료되었으며,
   **When** 사용자가 `open`으로 문제를 명시적으로 선택하면,
   **Then** 선택한 문제만 기본 브라우저로 열 수 있다.
   조회·추천만 수행할 때는 기본 브라우저로 문제를 자동으로 열지 않는다.

### Edge Cases

- 하한만 지정하거나 상한만 지정한 티어 조건에도 미정·미확인 제외가 적용된다.
- 미정과 미확인은 정상적인 데이터 상태이며, 표시 구조 누락·해석 불가능한 값은 조회 실패다.
  빈 값이라는 이유만으로 정상적인 미확인 상태라고 추정하지 않는다.
- 범위 밖 확정 티어는 미정·미확인과 다른 필터 적용 이상이다.
  실패 진단에는 문제 번호·읽은 값·요청 범위를 포함한다.
- 정답 제출 수의 생략한 경계는 제한하지 않는다. 음수·정수가 아닌 값·하한이 상한보다 큰 범위는 입력 오류다.
- 정답률이나 정답 제출 수가 명시적 미제공인 문제는 해당 지표 필터가 있을 때 제외하고 제외 개수를 안내한다.
  해당 필터가 없으면 포함해 미확인으로 표시하고 해당 지표 정렬에서 마지막에 둔다.
- 정답률과 정답 제출 수가 0인 상태도 유효하다. 정답률은 다른 통계로 재계산하지 않는다.
- 페이지 경계의 중복은 문제 번호 기준으로 한 번만 포함한다.
- 추가 목록 수집·사용자 확인·데이터 해석·접근 중 실패하거나 사용자가 취소하면,
  그때까지 확보한 일부 후보를 정상 완료된 결과로 출력하지 않는다.
- 사용자 없음·모호한 사용자·공개 풀이 이력 확인 실패를 미풀이로 간주하지 않는다.
- 데이터 수집 시간과 데이터 변화는 별개다. 목록 지표는 각 관측 시점의 값이며 동시 시점 일치를 보장하지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 티어 하한·상한 중 하나라도 지정하면 최초 목록과 모든 추가 목록에 지정 범위 및
  미정 문제 제외 조건을 유지해야 한다.
- **FR-002**: 티어 범위가 있을 때 정상적으로 식별된 미정·미확인 문제는 후보에서 제외하되,
  나머지 후보의 수집·조회·추천을 계속해야 한다. 정상적으로 전체 수집을 마친 후보 0개는 성공으로 처리해야 한다.
- **FR-003**: 범위 밖 확정 티어가 반환되면 필터 적용 이상으로 실패해야 하며,
  문제 번호·읽은 티어·요청한 하한과 상한을 진단에 포함해야 한다. 생략한 경계는 제한 없음으로 표시해야 한다.
- **FR-004**: 티어 범위가 없으면 정상적인 미정·미확인 문제를 포함하고 상태를 구분해 표시해야 한다.
  난이도 양방향 정렬에서 두 상태 모두 마지막에 두고 같은 미확정 그룹은 번호 오름차순이어야 한다.
- **FR-005**: 티어·정답 제출 수·정답률의 정상적인 미정·미제공과 표시 구조 누락·해석 실패를 구분해야 한다.
  후자는 문제 번호·대상 지표·읽은 값 또는 구조 누락 사실을 안내하고 조회 실패로 처리해야 한다.
- **FR-006**: 조회·추천의 필터·정렬·출력 지표는 맞힌 사람 수 대신 공개 목록의 정답 제출 수여야 한다.
  정답 제출 수는 동일 사용자의 중복 정답 제출을 포함하며 전체 제출 수·맞힌 사람 수와 혼동하면 안 된다.
- **FR-007**: 정답 제출 수는 0 이상의 정수로 처리하고 최소·최대 조건을 각각 또는 함께 제공해야 한다.
  지정한 경계를 포함하고 생략한 경계는 제한하지 않으며 잘못된 입력은 입력 오류로 처리해야 한다.
- **FR-008**: 정답 제출 수의 실제 0과 명시적 미제공을 구분해야 한다. 미제공은 해당 지표 필터가 있으면
  제외하고 제외 개수를 안내하며, 없으면 포함해 미확인으로 표시해야 한다.
- **FR-009**: 정답 제출 수의 오름차순·내림차순을 지원하고 전체 적격 후보를 정렬한 뒤 표시 개수를
  제한해야 한다. 동점은 번호 오름차순, 미확인은 양방향 모두 마지막이어야 한다.
- **FR-010**: 정답률은 공개 목록에 표시된 값과 정밀도를 그대로 사용해야 하며,
  정답 제출 수·전체 제출 수·맞힌 사람 수를 이용해 재계산하지 않아야 한다.
- **FR-011**: 일반 조회·추천은 목록에서 확인한 데이터만으로 완료해야 한다.
  조건·정렬·표시·추천 개수와 관계없이 문제 상세 탐색과 상세 통계 보충을 수행하지 않아야 한다.
  지정 공개 사용자 확인에 필요한 조회는 허용한다.
- **FR-012**: 기존 난이도 범위·정답률 범위·지정 공개 사용자의 푼 문제/안 푼 문제 조건을 함께 사용할 수 있어야 한다.
  최초·추가 목록 모두 지정 사용자 기준을 유지하고 로그인한 사용자의 풀이 상태로 대체하지 않아야 한다.
- **FR-013**: 표시·추천 개수와 관계없이 전체 목록 수집을 완료한 뒤 필터·정렬·추천해야 한다.
  중복 문제는 번호 기준으로 제거하고 적격 후보 각각에 동일한 추천 기회를 부여해야 한다.
- **FR-014**: 적격 후보가 충분하면 요청 개수만큼 중복 없이 추천하고, 부족하면 전부와 부족 안내를 반환해야 한다.
  실패·취소를 후보 부족·정상 빈 결과로 처리하거나 일부 후보로 최종 결과를 반환하지 않아야 한다.
- **FR-015**: 새 지표의 사용자 옵션은 `--min-accepted`·`--max-accepted`·`--sort accepted`로 제공해야 한다.
  기존 solver 옵션은 입력 오류로 거부하고 대응 옵션 및 지표의 의미 변경을 안내해야 한다.
- **FR-016**: 도움말·결과 제목·적용 조건 요약·사용 예시에서 정답 제출 수라는 명칭과 중복 정답 제출 포함 의미를
  일관되게 설명해야 한다. 변경에 관련된 명세·계획·데이터 정의·계약·사용법·검증 자료도 새 의미와 일치해야 한다.
- **FR-017**: 진행 안내는 목록 수집과 결과 처리의 실제 상태 및 취소 방법을 보여야 한다.
  제거된 상세 통계 수집 단계를 안내하지 않고, 입력 오류·조회 실패·취소·정상 완료를 기존처럼 구분해야 한다.
- **FR-018**: 명시적인 `open`으로 선택한 문제를 여는 기능을 유지해야 한다.
  조회·추천만 실행하면 기본 브라우저로 문제를 자동으로 열지 않아야 한다.
- **FR-019**: 변경 전후 동일한 후보 집합과 비교 가능한 조건으로 소요 시간을 비교한 기록을 남겨야 한다.
  전체 소요 시간과 전체 목록 수집 시간을 구분하고, 지표 변경으로 조건의 의미가 달라진 비교는 별도로 표시해야 한다.
- **FR-020**: 자동 데이터 접근은 기존에 확인한 허용 범위와 접근 제한 처리 원칙을 유지해야 한다.
  상세 조회 제거를 이유로 허용 여부가 확인되지 않은 접근 경로를 추가하지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **목록 문제**: 번호, 제목, 링크, 티어 또는 미정·미확인 상태, 정답률 또는 명시적 미제공 상태,
  정답 제출 수 또는 명시적 미제공 상태, 목록 관측 시점. 상세 통계 확보를 전제하지 않는다.

- **검색 조건**: 티어·정답률·정답 제출 수 범위, 지정 공개 사용자와 풀이 조건, 정렬 기준·방향, 표시·추천 개수.
- **수집 진단**: 문제 번호, 대상 지표, 읽은 값 또는 구조 누락, 요청 범위와 실패 원인.
- **조회·추천 결과**: 전체 수집 완료 여부, 적용 조건, 중복 제거된 적격 후보 수, 지표 미확인으로 제외한 개수,
  표시·추천 문제와 실제 개수, 부족 안내, 조회 시점.
- **시간 비교 기록**: 변경 전후의 비교 조건·후보 수·반복 횟수, 전체 소요 시간과 목록 수집 시간,
  상세 조회 횟수, 지표 변경에 따른 비교 제약.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 첫 목록·추가 목록 및 티어 양쪽·한쪽 경계 사례 모두에서 정상적인 미정·미확인으로 인한
  중단은 0건이며, 반환 문제의 100%가 지정 티어 범위를 만족한다.
- **SC-002**: 범위 밖 확정 티어·표시 구조 누락·해석 실패 사례의 100%가 원인이 구분된 실패로 안내된다.
  범위 밖 티어 진단의 100%에 문제 번호·읽은 티어·요청 범위가 포함된다.
- **SC-003**: 정답 제출 수의 0·최소·최대 경계·한쪽 경계·미제공 및 다른 수치와의 구분 사례에서
  필터·출력 결과가 기대값과 100% 일치한다. 목록 정답률 표시값과 결과의 수치는 100% 일치한다.
- **SC-004**: 양방향 정답 제출 수 정렬의 결과가 전체 적격 후보 기준 기대 순서와 100% 일치하고,
  표시 개수를 줄인 결과는 전체 정렬의 앞부분과 일치한다.
- **SC-005**: 정답 제출 수 조건 유무, 추천 1개, 여러 목록을 포함한 조회·추천 검증 사례에서
  문제 상세 조회는 모두 0건이며 필요한 전체 후보는 누락 없이 처리된다.
- **SC-006**: 충분·부족·0개 후보 검증에서 반환 개수와 안내가 기대값과 100% 일치하고 결과의 중복은 0개다.
  실패·취소 사례에서 일부 후보로 만든 최종 결과 출력은 0건이다.
- **SC-007**: 세 가지 기존 solver 옵션 사용 사례 모두에서 입력 오류와 대응하는 새 사용법이 안내된다.
  사용자는 문서의 새 예시로 조건 지정 → 조회·추천 → 선택한 문제 열기를 코드 수정 없이 수행할 수 있다.
- **SC-008**: 같은 환경과 고정된 여러 목록의 후보 집합으로 변경 전후 각각 3회 이상 비교했을 때,
  상세 조회를 제거한 뒤 전체 소요 시간의 중앙값이 감소한다. 각 실행의 전체·목록 수집 시간과 후보 수를 기록한다.

## Assumptions

- 범위는 ISSUE-001·ISSUE-002다. [001 스펙](../001-jungol-problem-picker/spec.md)의 맞힌 사람 수 요구사항과
  상세 통계 수집 전제는 이번 기능에서 정답 제출 수와 목록 전용 처리로 대체한다.
  새 기능의 계획·계약·검증은 이 변경을 기준으로 작성하고 001 문서는 기존 동작의 이력으로 참조한다.
- 새 옵션 이름은 지표의 의미를 드러내는 `accepted`로 정한다. 기존 solver 옵션을 새 지표의 별칭으로
  재사용하지 않고 전환 안내가 있는 입력 오류로 처리하는 것을 기본 전환 정책으로 삼는다.
- 범위 밖 확정 티어 반환은 기존의 실패 정책을 유지한다. 원인 확인 없이 정상 후보 제외로 숨기지 않으며,
  이번 수정으로 수집을 계속하도록 바꾸는 대상은 정상적으로 식별된 미정·미확인뿐이다.
- 문제 목록과 지표는 허용된 공개 목록에서 확보 가능하다는 기존 조사에 의존한다.
  정상적인 미제공 표시는 확인된 표시 규칙을 기준으로 식별하고, 새 표시를 임의로 미확인으로 간주하지 않는다.
  구체적인 수집 방식과 필터 전달 방법은 원문 이슈의 제약을 따라 계획 단계에서 정한다.
- 정답 제출 수에는 중복 정답 제출이 포함되므로 기존 맞힌 사람 수 필터와 같은 숫자를 넣어도
  결과가 달라질 수 있다. 원문의 1006번 관측 수치는 의미를 설명하는 예시이며 고정 기대값이 아니다.
- 원문에 실측 지연 시간이 없으므로 절대 완료 시간이나 개선율을 미리 보장하지 않는다.
  시간 비교는 반복 가능한 같은 조건으로 수행하며 전체 목록 수집에 필요한 시간은 남는다.
- 공개 사용자 기준, 기존 기본 정렬·표시·추천 개수, 실패·취소 구분과 명시적 열기는 유지한다.
  사용자 로그인, 비공개 이력, 수동 풀이 기록, 다른 플랫폼 지원은 추가하지 않는다.
- 로컬 캐시·오프라인 조회·시간 제한에 따른 부분 결과·번호순 목록의 조기 종료(IDEA-001)는 포함하지 않는다.
