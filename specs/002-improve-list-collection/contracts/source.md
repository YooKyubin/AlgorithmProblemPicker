# Source Contract: 공개 목록 전용 수집

**Spec**: [spec.md](../spec.md) | **Model**: [data-model.md](../data-model.md)

이 문서는 외부 공개 화면과 도메인을 분리하는 내부 경계다.
사용자 인터페이스는 [CLI 계약](cli.md)을 따른다.

## 최소 경계와 수명

- `resolve_user(handle) → UserReference`: 공개 사용자 선택 UI에서 정확한 핸들을 확인한다.
- `collect(criteria, user) → CompletedListing`: 일반 문제 목록 전체를 읽어 고유 Problem을 반환한다.
- `read_details`는 제거한다. 상세 정보를 보충하는 우회 경로도 제공하지 않는다.

Protocol은 하나만 유지한다. Playwright·DOM 로케이터·사이트 URL 매개변수는 공급자 밖에서 참조하지 않는다.
성공·실패·Ctrl+C 모두에서 공급자가 브라우저 수명을 정리한다.
비영구 컨텍스트 한 개와 목록용 페이지 한 개를 사용하고 상세용 페이지는 만들지 않는다.
문제·사용자 매핑·프로필·storage_state·HAR·추적 파일을 다음 실행용으로 저장하지 않는다.

## 목록 조건

| 조건 | 전달 및 검증 |
| --- | --- |
| 일반 문제·기본 순서 | `type=problem`, `sort=idAsc`. 서버 난이도 정렬은 사용하지 않음. |
| 티어 하한/상한 | 지정한 `minTier`, `maxTier`만 전달. |
| 미정 포함 여부 | 티어 경계가 하나라도 있으면 `unrated=exclude`, 없으면 include. |
| 지정 사용자 | 확인된 account_id를 `solvedBy`, solved는 `solvedByMode=include`, unsolved는 exclude. |
| 정답률·정답 제출 수 | 전체 수집 후 로컬 필터. 확인되지 않은 서버 옵션을 추가하지 않음. |

첫 목록뿐 아니라 다음 페이지·더 불러오기 후에도 URL의 필수 조건과 공개 필터 UI의 적용 상태를 확인한다.
중복 URL 값·누락·다른 범위·사용자/모드 변경 등 조건 손실은 오류다.
사이트 자체 커서/페이지 이동 값은 허용하지만 필터 의미를 바꾸면 안 된다.
`status=solved/unsolved` 등 로그인 사용자용 조건으로 대체하지 않는다.
적용 여부 확인을 위해 내부 API 요청·응답·앱 전역 상태를 해독하지 않는다.

## 행 추출

공개 목록의 의미 있는 헤더로 표를 식별하고 각 문제 행 내부에서 읽는다.

| 항목 | 계약 |
| --- | --- |
| id/url | 해당 행의 유일한 정올 `/problem/<양의 정수>` 링크. |
| title | 해당 문제 링크의 유일한 제목 텍스트. |
| tier | 해당 문제의 `/solved/<1~30>.svg`, 또는 아래의 명시적 상태. |
| pass_rate | 해당 행의 정답률 셀. 기존 허용 표시를 Decimal로 파싱. |
| accepted_count | 해당 행의 `td[data-col="정답"]` 정확히 한 개. |
| listed_at | 목록 관측 시점. |

`시도` 셀·상세 맞힌 사람 통계·전체 화면 첫 숫자를 정답 제출 수로 읽지 않는다.
고정 열 번호·해시 CSS 클래스·색상에 의존하지 않는다.
정답률은 목록 관측값과 정밀도를 유지하며 다른 지표로 재계산하지 않는다.

### 정상 상태와 오류

- 티어 미정: `/solved/0.svg` 또는 기존에 확인한 `.pl-row-link`의 제목이 있고 배지/이미지가 없는 정상 표현.
- 티어 미확인: 해당 문제의 명시적 `[title="난이도 미확인"]` 표현.
- 임의의 배지 누락·중복 배지·알 수 없는 배지·해석할 수 없는 티어는 `SourceSchemaError`다.
- 정답 제출 수: 바깥 공백 제거 후 `0`을 포함한 ASCII 정수 또는 정상 천 단위 쉼표 정수. 예: `3145`, `3,145`.
  `31,45`, 음수, 소수, 임의 설명 문자열은 오류다.
- 정답 제출 수의 `-`, `—`, `미확인`, `미제공`은 명시적 미제공 상태로 정한 계약이다.
  이 표식이 실제 정답 열에서 관측됐다고 주장하지 않는다. 근거의 한계는 [research](../research.md)에 기록했다.
- 정답 셀의 빈 문자열·빈 앵커·누락·중복은 오류다. 정답률에 있던 빈 링크 예외를 정답 셀에 복사하지 않는다.
- 정답률은 기존 명시적 미제공 표식과 해당 문제를 가리키는 확인된 빈 링크 표현만 미제공으로 인정한다.
  다른 빈 값·범위 밖 수치·미해석 표시를 정상 부재로 바꾸지 않는다.

스냅샷 준비 판정은 목록의 로딩·접근 상태와 필요한 공개 결과 반영을 확인해야 한다.
일시적 빈 값이나 요청 전송 완료만으로 값을 확정하지 않는다. 고정 대기 증가로 준비를 추정하지 않는다.

## 티어 범위 검증

- 범위가 있을 때 확정 `Rated`가 범위를 벗어나면 `SourceAccessError`로 종료한다.
  진단은 문제 번호·읽은 티어·요청 하한/상한이며 생략한 경계는 제한 없음으로 표시한다.
- 정상 `Unrated`와 `Unavailable`은 필터 적용 오류가 아니다. 수집 레코드에는 보존하고
  전체 완료 후 순수 티어 필터가 후보에서 제외한다.
- 범위가 없으면 세 상태 모두 수집한다. 상태의 표시와 정렬은 CLI/순수 처리 계약을 따른다.
- 일반 구조/파싱 오류는 문제 번호(확인 가능할 때)·대상 지표·읽은 값 또는 구조 누락 사실을 안내한다.
  번호도 해석할 수 없으면 원시 링크와 번호 확인 실패 사실을 포함한다.

## 전체 완료와 중복

번호 페이지는 공개 다음 링크를 따르고 커서 목록은 더 불러오기 버튼으로 진행한다.
누적 DOM의 고유 ID를 합치며 중복 ID는 최초 관측 레코드를 유지한다.
표시/추천 개수·정답률·정답 제출 수 조건을 이유로 수집을 조기 종료하지 않는다.

추가 로드마다 접근 상태와 로딩 종료, 해당 동작의 새 ID 또는 입증된 정상 종료를 확인한다.
버튼이 잠깐 사라짐·요청 전송 완료·같은 스냅샷 두 번만으로 최종 종료를 확정하지 않는다.
반복 페이지·진행 없음·완료 증거 부족은 `SourceCompletenessError`다.
실패·취소 시 CompletedListing 또는 부분 최종 결과를 반환하지 않는다.

001 T041·T042는 위 완료/사용자 확인 계약의 알려진 구현 결함이다. 002에 의해 자동 해결된 것으로 보지 않는다.
해당 경계는 별도 수정 결과를 확인하고 통합 수용에서 재검증해야 한다.

## 접근과 오류

기존 공개 DOM 접근 범위·최소 1초 시작 간격·30초 탐색/15초 DOM 기본 제한을 유지한다.
사이트가 자체 수행한 요청의 상태 감시는 가능하지만 본문 해독·직접 내부 API 호출은 하지 않는다.
403·429·챌린지·로그인 요구·다른 origin 이동은 실패이며 자동 재시도·우회하지 않는다.
사용자 없음/모호함, 접근 실패, 스키마 실패, 완전성 실패를 기존 SourceError 계열로 전달한다.
정상 후보 없음과 명시적 미제공은 오류와 구분한다.

## 관측과 최소 검증

로컬 검증은 허용된 fixture 요청만 공급하고 나머지는 차단한다.
list/recommend를 실제 수집 경로로 실행해 `/problem/<ID>` 문서 요청이 0건인지 확인한다.
조건 생략·요청 1개·여러 목록과 사용자 조건을 포함해 검사한다.
원격 내부 요청 본문을 읽어 상세 요청 횟수를 판단하지 않는다.
baseline용 상세 fixture와 계수 래퍼는 개발 검증 도구에만 두며 제품 Protocol에는 노출하지 않는다.
