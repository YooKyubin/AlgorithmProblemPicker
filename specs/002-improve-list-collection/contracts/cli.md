# CLI Contract: 정답 제출 수 기반 조회·추천

**Spec**: [spec.md](../spec.md)

아래는 002 구현 후의 계약이다. 현재 구현이 이미 이 동작을 제공한다는 뜻은 아니다.
기존 명령 이름·기본값·출력 채널·종료 상태는 유지하고 지표와 전환 정책을 변경한다.

## 명령과 옵션

```text
jpick list [FILTERS] [--sort id|difficulty|rate|accepted|random] [--order asc|desc] [--limit N]
jpick recommend [FILTERS] [--count N]
jpick open ID [ID ...]
jpick --help
jpick --version
```

| 공통 필터 | 형식·기본값 |
| --- | --- |
| `--min-tier`, `--max-tier` | 정수 1~30, 생략한 경계 제한 없음. 1=Bronze V, 30=Ruby I. |
| `--min-rate`, `--max-rate` | 유한 소수 0~100, % 없이, 생략한 경계 제한 없음. |
| `--min-accepted`, `--max-accepted` | 0 이상의 정수, 생략한 경계 제한 없음. 정답 제출 수. |
| `--status` | all(기본), solved, unsolved. |
| `--user` | 정확한 공개 핸들. @ 한 개 허용, 대소문자 보존. |

모든 지정 경계는 포함한다. 하한이 상한보다 크거나 형식·값 범위가 잘못되면 코드 2다.
solved/unsolved는 user가 필수이고 all+user는 입력 오류다.
풀이 기준은 지정 공개 사용자이며 현재 로그인 사용자가 아니다. 오답만 있는 문제도 unsolved다.

list 기본값은 id/asc/limit=20, recommend 기본 count=1이다. 개수는 양의 정수다.
random+desc는 입력 오류다. limit/count는 전체 수집 범위를 줄이지 않는다.

## 지표의 의미

정답 제출 수는 정답으로 처리된 제출 횟수이며 동일 사용자의 중복 정답 제출도 포함한다.
맞힌 사람 수와 전체 제출 수는 다른 지표다. 예를 들어 `--min-accepted 1000`은 1,000명 이상이 푼 문제가 아니라
정답 제출이 1,000건 이상인 문제를 뜻한다.
정답률은 목록 표시값을 그대로 사용하며 정답 제출 수로 다시 계산하지 않는다.

## 이전 옵션의 거부와 전환 안내

| 기존 입력 | 대응 안내 | 결과 |
| --- | --- | --- |
| `--min-solvers N` | `--min-accepted N` | 입력 오류 2, 조회 시작 안 함. |
| `--max-solvers N` | `--max-accepted N` | 입력 오류 2, 조회 시작 안 함. |
| `list --sort solvers` | `list --sort accepted` | 입력 오류 2, 조회 시작 안 함. |

- 전환 안내에는 맞힌 사람 수 지원이 정답 제출 수로 바뀌었으며 동일한 숫자라도 결과가 달라질 수 있음을 설명한다.
- 기존 입력은 새 지표의 별칭으로 동작하지 않는다. 새 옵션과 섞어도 옛 입력을 무시하지 않고 거부한다.
- 오류는 브라우저·공급자 생성과 사용자/문제 수집 전에 발생한다. stdout에 최종 결과는 없다.
- 일반 도움말의 지원 옵션과 정렬 값에는 accepted만 표시한다. 레거시 범위 옵션을 인식하는 코드는 거부 안내용이다.
- 각 명령의 도움말과 버전 확인은 네트워크·브라우저 생성 없이 완료한다.

## 결과와 정렬

stdout의 표는 번호·제목·난이도·정답률·정답 제출 수·문제 링크를 제공한다.
조건 요약은 새 지표 이름과 경계를 사용하고, 기준 사용자가 있으면 정확한 핸들과 풀이 조건을 표시한다.
조회 고유 개수·전체 적격 개수·요청/표시 또는 반환 개수·조회 시각을 안내한다.
추천은 실제 개수와 부족 수를 함께 안내한다.

- 실제 0은 0, 명시적 미제공은 미확인, 티어 미정은 미정으로 표시한다.
- 활성 지표 필터에서 미확인 때문에 제외한 개수는 stderr로 안내한다. 자세한 집계 규칙은 [데이터 모델](../data-model.md)을 따른다.
- 티어 경계가 하나라도 있으면 정상 미정·미확인 티어는 제외하되 수집은 계속한다. 경계가 없으면 포함한다.
- 양방향 지표 정렬은 미정·미확인을 마지막에 두며 지표 동점과 미확정 그룹 내부는 번호 오름차순이다.
- 목록의 각 관측 시점 값임을 안내한다. 상세 관측 시각이나 맞힌 사람 수를 현재 결과의 근거로 설명하지 않는다.

전체 목록을 수집한 뒤 필터·정렬·표시 제한 또는 추천을 수행한다.
추천은 전체 고유 적격 후보에 동일한 선택 기회를 주며 요청 개수까지 중복 없이 선택한다.
부족하면 가능한 전부를 반환하고 후보 0개는 정상 성공으로 안내한다.
정상 조회·추천의 문제 상세 페이지 요청은 0건이다. 공개 사용자 확인에 필요한 목록 탐색은 허용한다.

## 진행·실패·취소

stderr에는 실제 수집/결과 처리 단계, 확인한 수집 개수, Ctrl+C 취소 방법을 표시한다.
상세 통계 보강 단계와 상세 확인 개수는 표시하지 않는다.
알 수 없는 전체 페이지 수·남은 시간을 만들어 표시하지 않는다.

| 종료 코드 | 의미 |
| --- | --- |
| 0 | 완전한 성공. 후보 0개·추천 부족 포함. |
| 1 | 접속·사용자 확인·구조/파싱·필터 적용·완전성·브라우저 전달 실패. |
| 2 | 잘못된 옵션·값·범위·개수·사용자 조건·기존 solver 입력. |
| 130 | Ctrl+C 취소. |

범위 밖 확정 티어 진단에는 문제 번호·읽은 티어·요청 범위를 표시한다.
구조·파싱 실패를 정상 미제공이나 빈 결과로 바꾸지 않는다.
실패·취소 시 부분 최종 표·추천 결과를 출력하지 않으며 조회용 브라우저를 정리한다.

## 명시적 문제 열기

`open`은 양의 정수 번호를 한 개 이상 받아 입력 순서대로 중복을 제거하고 기본 브라우저에 한 번씩 전달한다.
별도 문제 수집·상세 통계 읽기·로그인 없이 링크를 연다. 실패 시 모든 요청 링크와 실패 번호를 안내한다.
이는 선택한 문제를 열기 위한 명시적 동작이며 목록 전용 수집의 상세 요청 0건 조건과 구분한다.
list/recommend만 실행하면 기본 브라우저로 문제를 열지 않는다.

JSON 출력, 별칭으로 옛 solver 의미 유지, 영구 캐시, 조기 종료, 부분 결과는 추가하지 않는다.
