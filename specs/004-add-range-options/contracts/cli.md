# CLI Contract: 티어·정답률·정답 제출 수 범위 옵션

**Spec**: [spec.md](../spec.md) | **Model**: [data-model.md](../data-model.md)

004에서 추가하는 사용자 입력 계약이다. [003 CLI 계약](../../003-align-site-listing/contracts/cli.md)의 기존 동작을 승계하되, 새 옵션을 추가하지 않는다는 당시 범위 제한은 이 세 옵션에 한해 대체한다.

## 명령 표면

`jpick list`와 `jpick recommend`는 아래 세 옵션을 각각 최대 한 번 받는다. 한 옵션은 범위 값 인자 하나를 받는다.

| 옵션 | 허용 경계 | 닫힌 범위 | 하한만 | 상한만 |
| --- | --- | --- | --- | --- |
| --tier | 1~30 정수, 사이트 검색 조건 | `9..13` | `9..` | `..13` |
| --rate | 0~100 정수·소수, % 없이 | `40.5..80` | `40.5..` | `..80` |
| --accepted | 0 이상의 정수, 중복 정답 제출 포함 | `500..1000` | `500..` | `..1000` |

범위는 모두 양 끝 포함이다. 한쪽 생략은 해당 방향의 추가 제한이 없다는 뜻이며, 도메인의 유효 수치 범위는 유지된다. 두 경계가 같으면 유효하다. `--tier 9..9`도 표시 티어가 정확히 9인 문제만 반환한다는 보장은 아니다.

옵션과 값을 구분하는 일반 표기와 `--accepted=500..1000` 같은 등호 표기를 모두 지원한다. 셸에서 따옴표로 값을 감싸도 인자 내용의 규칙은 같다.

## 값 문법

```text
integer = ASCII 숫자 한 개 이상
decimal = integer 또는 integer "." integer
tier-range / accepted-range =
    integer ".." integer | integer ".." | ".." integer
rate-range =
    decimal ".." decimal | decimal ".." | ".." decimal
```

구분자 `..`는 정확히 하나다. 정답률 소수점은 앞뒤에 숫자가 있어야 한다. 선행 0은 허용한다. 문자열 전체가 문법과 맞아야 하며 경계 변환 뒤 각 수치 제한과 하한≤상한을 적용한다.

거부 사례:

| 종류 | 입력 예 | 이유 |
| --- | --- | --- |
| 값 없음 | `--accepted` | 옵션에 값 인자가 필요 |
| 빈 값·양쪽 생략 | `--accepted=`, `--accepted ..` | 유효한 경계가 없음 |
| 단일값·구분자 오류 | `500`, `500...1000`, `500..750..1000` | 계약의 범위 형태가 아님 |
| 경계 역전 | `1000..500` | 하한이 상한보다 큼 |
| 부호·구분기호·단위 | `+500..1000`, `1,000..`, `40%..80%` | 지원하지 않는 경계 표기 |
| 공백·지수·비유한 값 | ` 500..1000`, `1e2..`, `NaN..100`, `0..Infinity` | 숫자 문법 위반 |
| 숫자 종류 | `--tier 1.0..5`, `--accepted 0..1.5`, 비ASCII 숫자 | 정수 또는 ASCII 규칙 위반 |
| 허용 수치 밖 | `--tier 0..5`, `--tier 1..31`, `--rate 0..100.1`, `--accepted=-1..5` | 해당 지표의 범위 위반 또는 음수 문법 위반 |

앞뒤 공백 제거, 반올림, 부호·%·쉼표 제거, 단일값 자동 확장을 하지 않는다.

## 기존 옵션과 조합

- 여섯 `--min-tier`·`--max-tier`·`--min-rate`·`--max-rate`·`--min-accepted`·`--max-accepted`는 기존 이름·문법·기본값·진단을 유지한다.
- 같은 지표의 새 옵션과 기존 min 또는 max가 함께 있으면 값과 순서에 관계없이 거부한다. 같은 경계나 한쪽씩 보완하는 입력도 예외가 아니다.
- 예: `--accepted 500.. --max-accepted 1000`과 `--min-accepted 0 --accepted 0..1000`은 오류다.
- 서로 다른 지표는 신·구 표기를 자유롭게 섞는다. `--tier 9..13 --min-rate 40.5 --accepted 500..`는 유효하다.
- 같은 새 옵션을 두 번 지정하면 같은 값이어도 오류다. 등호 표기와 일반 표기를 섞은 반복도 같다.
- 기존 경계 옵션 자체의 반복 처리와 숨겨진 solver 옵션 거부 정책은 변경하지 않는다.
- 사용자 풀이 조건·정렬·개수와의 기존 조합 규칙도 유지한다. `open`에는 새 범위 옵션을 추가하지 않는다.

## 오류·종료·출력

| 상황 | 종료 | 관측 결과 |
| --- | --- | --- |
| 새 옵션 값 누락 | 2 | Typer 기본 오류에 옵션명과 값이 필요하다는 이유 |
| 전달된 값의 문법 오류 | 2 | 해당 옵션, 이유, 유효 범위 예시 |
| 수치 제한·역전 | 2 | 해당 옵션과 허용 수치 또는 순서 이유 |
| 신·구 표기 충돌 | 2 | 새 옵션과 충돌한 기존 옵션, 한 표기만 사용 안내 |
| 새 옵션 반복 | 2 | 해당 옵션, 한 번만 지정 안내 |
| 정상 결과·빈 결과·추천 부족 | 0 | 기존 결과·집계·조건·부족 안내 |
| 접근·수집 실패 / 취소 | 1 / 130 | 기존 실패·취소 처리와 조회 자원 정리 |

입력 오류는 stderr에 알리고 stdout에 결과를 제공하지 않는다. 공급자 생성·브라우저 시작·조회 시작 안내 전에 실패해야 한다. 둘 이상의 입력 오류가 있으면 어떤 오류를 먼저 보여줄지 고정하지 않는다.

새 표기와 기존 표기는 같은 SearchCriteria 경계로 이어진다. 결과 조건은 기존 min/max 이름으로 표시해도 되며 모든 지정 경계를 정확히 표시하고 생략된 경계를 추가하지 않는다. 실행 시각·변하는 원격 관측·무작위 표본 자체의 일치를 요구하지 않는다.

미제공 지표·실제 0·범위 밖 Rated·고유 후보 집계·정렬·표시 제한·중복 없는 추천·수집 종료·상세 요청 금지는 003 계약과 같다.

## 도움말과 사용 안내

두 명령의 도움말은 세 새 옵션, 경계 타입·수치, 양 끝 포함, 열린 범위, 최대 1회, 같은 지표 혼용 제한과 기존 경계 옵션 유지를 설명한다. 티어가 사이트 검색 조건이며 표시 티어의 범위 일치를 보장하지 않음도 유지한다.

README에는 다음 두 용도를 각각 하나 이상 제공한다.

```powershell
uv run --locked jpick list --tier 9..13 --rate 40.5..80 --accepted 500..1000 --sort accepted --order desc --limit 5
uv run --locked jpick recommend --tier 9.. --rate ..80 --accepted 500.. --count 3
```

이 문서는 구현 후 계약이다. 작성 시점에 제품이 새 옵션을 지원한다는 뜻은 아니다.
