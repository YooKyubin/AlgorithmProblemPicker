# Data Model: 범위 입력과 기존 검색 조건

**Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md) | **Contract**: [cli.md](contracts/cli.md)

## 1. 원시 범위 옵션

CLI 내부의 일시적 입력이다. 새 도메인 엔티티·영구 저장 구조를 만들지 않는다.

| 속성 | 표현 | 규칙 |
| --- | --- | --- |
| 지표 | tier / rate / accepted | 명령의 옵션 이름으로 결정한다. 사용자에게 별도 지표 인자를 받지 않는다. |
| 출현 값 | list[str] | 0개는 생략, 1개는 범위 해석 대상, 2개 이상은 입력 오류다. |
| 값 원문 | str | 따옴표를 제거한 셸 인자 그대로 검사한다. trim·기호 제거·자동 보정은 하지 않는다. |

각 새 옵션의 기본값은 빈 목록이다. 공통 callback과 조건 해석기는 수신 목록·기본 목록을 수정하지 않는다. 반복 여부를 놓치지 않도록 단일 문자열로 먼저 축약하지 않는다. 원시 목록은 CLI 밖으로 전달하지 않는다.

## 2. 해석된 경계 쌍

비공개 helper의 반환값으로 하한·상한 쌍을 사용한다. 별도 공개 Range 클래스나 영속 모델은 필요하지 않다.

| 지표 | 경계 타입 | 수치 범위 | 최종 필드 |
| --- | --- | --- | --- |
| tier | int 또는 None | 1~30 | min_tier, max_tier |
| rate | Decimal 또는 None | 0~100 | min_rate, max_rate |
| accepted | int 또는 None | 0 이상 | min_accepted, max_accepted |

- `None`은 생략된 경계다. 실제 숫자 0과 구분해야 한다.
- 새 옵션이 지정되면 적어도 한 경계가 있어야 한다. 양쪽 경계가 있으면 하한≤상한이어야 한다.
- 소수는 정답률에서만 허용하며 Decimal로 직접 변환한다.
- 새 옵션이 생략되면 같은 지표의 기존 min/max 값을 사용한다.
- 새 옵션이 있고 같은 지표의 기존 경계 중 하나라도 None이 아니면 충돌이다. 값이 0이거나 서로 같은 범위라도 예외를 두지 않는다.
- 새 옵션이 없는 지표는 기존 문법과 검증을 따른다. 새 옵션의 엄격한 문법을 기존 옵션에 소급하지 않는다.

## 3. SearchCriteria

기존 frozen dataclass와 여섯 경계 필드, status·user_handle을 그대로 사용한다. 데이터베이스·마이그레이션·새 공개 필드는 없다.

| 새 입력 | 대응하는 기존 조건 |
| --- | --- |
| `--tier 9..13` | min_tier=9, max_tier=13 |
| `--rate 40.5..` | min_rate=Decimal('40.5'), max_rate=None |
| `--accepted ..1000` | min_accepted=None, max_accepted=1000 |
| `--accepted 0..0` | min_accepted=0, max_accepted=0 |
| 모든 새·기존 경계 생략 | 여섯 경계 모두 None |

기존 `SearchCriteria.__post_init__`의 타입·수치·순서·사용자 조건 불변식은 직접 모델을 생성하는 다른 호출자를 위해 유지한다. CLI는 새 표기의 문법·충돌·수치 오류에 해당 옵션명을 붙이는 책임을 맡는다. 서비스와 필터는 유효한 SearchCriteria를 받아 기존 처리를 수행하며 새 검사를 반복하지 않는다.

## 4. 결과·오류

`Problem`, `Known`, `Unavailable`, `Rated`, `Unrated`, `Result`는 변경하지 않는다. Result.criteria에는 입력 표기와 관계없이 같은 경계를 저장한다. 기존 min/max 조건 출력이 각 지정 경계를 알리고 생략된 경계는 출력하지 않는다.

오류를 위한 새 도메인 타입도 만들지 않는다.

| 검증 | 책임 위치 | 표현 |
| --- | --- | --- |
| 옵션 값 누락 | Typer 인자 파싱 | 기본 필수 값 오류, 해당 옵션·이유, 종료 2 |
| 새 옵션 반복 | 공통 callback | BadParameter, 해당 옵션, 한 번만 사용 안내 |
| 같은 지표의 신·구 표기 혼용 | 공통 조건 생성의 충돌 검사 | BadParameter, 새 옵션과 충돌한 기존 옵션 |
| 값 문법·수치 제한·순서 | 비공개 범위 해석기 | BadParameter와 정확한 param_hint, 문법 오류에는 유효 예시 |
| 기존 모델 불변식 | SearchCriteria 초기화 | 기존 ValueError를 CLI의 기존 BadParameter 경로로 전달 |

둘 이상의 오류가 함께 있으면 첫 진단의 우선순위는 고정하지 않는다. 어떤 경우에도 공급자 생성 전에 실패해야 한다.

## 5. 입력 상태 전이

`인자 수신 → 새 옵션 반복 검사 → 같은 지표 혼용 검사 → 문법/숫자/순서 해석 → 기존 SearchCriteria 생성 → 기존 _run`

Typer가 값 누락이나 알 수 없는 옵션을 먼저 거부할 수 있다. 중간 단계 실패는 종료 코드 2와 stderr 진단으로 끝나며 공급자 생성·조회 시작 안내·결과 출력은 없다. 정상 진행·실패·취소의 기존 서비스 상태 전이는 변경하지 않는다.

## 6. 보존해야 할 의미

- 티어 경계는 사이트 검색 조건이다. 범위 밖 확정 티어를 재필터링하지 않고 범위가 지정됐을 때 미정·미확인을 기존대로 제외한다.
- 정답률·정답 제출 수는 양 끝 포함 수치 필터다. 지표가 미제공이면 활성 필터에서 제외하고 실제 0은 0으로 처리한다.
- 수집 완료 후 전체 적격 후보에 대해 기존 정렬·추천을 수행한다.
- 추천은 중복이 없고 결과 부족과 빈 결과는 정상 완료다.
