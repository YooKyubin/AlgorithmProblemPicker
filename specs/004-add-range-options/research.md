# Research: 범위 옵션의 CLI 통합

**Date**: 2026-10-28 | **Spec**: [spec.md](spec.md) | **Plan**: [plan.md](plan.md)

제품 코드를 변경하지 않고 현재 저장소·잠금 환경과 설치 라이브러리 소스를 조사했다. Phase 0 연구 에이전트가 Typer 입력 동작을 메모리 내 최소 프로그램으로 확인했다. 외부 서비스나 최신 버전 일반론 대신 실제 잠금 버전의 동작을 근거로 삼았다.

## R1. 옵션 출현 횟수 보존

**Decision**: 새 옵션만 Typer의 `list[str]` 옵션으로 선언하고 기본값은 빈 목록으로 둔다. 공통 callback은 두 번 이상 지정되면 `typer.BadParameter`로 거부하고, 0회·1회는 값을 변경하지 않고 반환한다. `MIN..MAX` metavar와 도움말로 한 범위만 허용함을 설명한다.

**Rationale**: 단일 문자열 옵션은 반복 시 마지막 값만 남아 FR-009를 충족하지 못한다. 문자열 목록은 각 출현을 보존하면서 기존 CLI 선언 방식을 유지한다. 기본 빈 목록과 수신 목록을 수정하지 않으므로 공유되는 mutable 기본값에 상태를 남기지 않는다.

**Evidence**: 설치된 Typer 0.27.3의 `.venv/Lib/site-packages/typer/main.py`에서 `get_click_param`은 list를 `multiple=True`로 연결하고, `get_param_callback`은 BadParameter에 옵션 문맥을 부여한다. 독립 Click 배포판은 없고 `typer._click`이 내부 구현이다. 직접 import하거나 새 의존성으로 추가하지 않는다.

| 최소 실험 입력 | 관측 |
| --- | --- |
| 생략 | 빈 목록, 정상 |
| `--accepted 500..1000` | 문자열 한 개가 있는 목록, 정상 |
| 같은 값 또는 다른 값으로 두 번 | callback에서 옵션명 포함 종료 코드 2 |
| `--accepted=` | 빈 문자열 한 개가 전달됨. 범위 해석기가 거부해야 함 |
| `--help` | metavar를 지정해 범위 형태를 표시할 수 있음 |

**Alternatives considered**: 원시 argv에서 출현 횟수 계산은 `--name=value`·인자 경계 처리의 재구현이 필요하다. 단일 문자열의 마지막 값 우선은 명세 위반이다. Click 직접 확장이나 전역 monkeypatch는 필요하지 않다.

## R2. 문법과 정밀도

**Decision**: 비공개 범위 해석기에서 `..`가 정확히 하나인지 확인한 뒤 두 경계를 나누고 각 경계 전체를 검사한다. 정수는 `[0-9]+`, 정답률은 `[0-9]+(?:\.[0-9]+)?`만 허용한다. 양쪽 빈 값은 거부한다. 정수는 int, 정답률은 Decimal로 변환한다.

**Rationale**: 일반 숫자 변환만 사용하면 공백·부호·비ASCII 숫자·지수 등의 비계약 표기를 받아들일 수 있다. 분리 후 경계 전체 검사로 `1...2`·`1..2..3`·`1.0..2.0`을 명확히 구분한다. Decimal은 기존 모델과 같은 정밀도를 보존한다. 선행 0은 숫자로 허용하되 의미를 바꾸지 않는다.

**Evidence**: 현재 `cli.py:_criteria`와 `models.py:SearchCriteria`가 정답률에 Decimal을 사용하고, 기존 `test_common_filters_and_exact_user_reach_service`가 47.45 전달을 검증한다.

**Alternatives considered**: float 변환·반올림, trim·기호 자동 제거, 숫자 하나를 같은 경계로 추정하는 방식은 명세와 맞지 않는다. 새 범위 DSL·공개 Range 클래스·외부 파서 라이브러리는 필요하지 않다.

## R3. 검증 위치와 오류 귀속

**Decision**: 반복 검사는 callback에서 수행한다. 혼용 검사는 모든 옵션 값이 준비된 공통 조건 생성 경로에서 수행한다. 범위 해석기는 새 입력의 문법·수치 제한·경계 역전을 검사하고 `param_hint='--tier'` 등으로 정확한 옵션을 붙인다. 이후 기존 SearchCriteria를 생성한다.

**Rationale**: callback에서 다른 옵션 값을 읽으면 인자·callback 처리 순서에 의존한다. 같은 지표의 기존 경계를 `is not None`으로 검사해야 기존 값 0도 충돌로 판정한다. CLI 검사는 사용자 입력 진단을 맡고 모델 검사는 직접 Python 호출에서도 지켜야 하는 불변식을 맡는다. 이 두 진입점의 책임을 유지하되 서비스·필터에 검사를 더하지 않는다.

**Evidence**: `cli.py`의 두 명령은 현재도 SearchCriteria 생성 후에만 `_run`을 호출하며, `_run` 안에서 공급자를 생성한다. `models.py:SearchCriteria.__post_init__`가 기존 타입·수치·순서·사용자 조건을 검증한다. 기존 CLI 정수 옵션도 입력 제한과 모델 불변식을 함께 유지한다.

**Alternatives considered**: 모델 오류 문자열로 지표를 추정하면 문구에 결합된다. 새 도메인 예외나 지표별 임시 SearchCriteria 생성은 작은 기능에 불필요하다. 여러 활성 옵션을 한꺼번에 오류 힌트로 붙이면 어느 지표가 잘못됐는지 흐려진다.

## R4. 값 누락과 기존 오류 보존

**Decision**: 새 옵션의 값 누락은 Typer의 기본 진단을 유지한다. 옵션명과 값이 필요하다는 이유를 포함한 종료 코드 2를 사용한다. 값이 전달됐으나 문법이 잘못된 경우에는 공통 해석기가 해당 옵션과 유효 예시를 제공한다.

**Rationale**: FR-010은 값 누락과 문법 오류를 구분해 열거하고 문법 오류에 예시를 요구한다. 누락은 실제 값이 없는 필수 인자 오류로 처리한다. 값이 전달된 `--accepted=`의 빈 문자열은 문법 오류여서 예시를 제공한다. 누락 메시지를 장식하기 위한 별도 명령 클래스를 추가하지 않는다.

**Evidence**: 설치된 `typer/_click/parser.py:_get_value_from_state`는 callback 이전에 값 누락을 거부한다. 실험에서도 `--accepted`는 옵션명 포함 종료 코드 2였다. 따라서 callback만으로 기본 누락 진단을 바꿀 수 없지만 변경할 필요도 없다.

**Alternatives considered**: 작은 TyperCommand 하위 클래스로 누락 예시를 추가하는 방식도 조사했으나, 이미 계약을 충족하는 진단을 변경하고 버전 결합 지점을 늘리므로 채택하지 않는다. 기존 옵션 누락·알 수 없는 옵션·숨겨진 solver 오류의 동작도 그대로 유지한다.

## R5. 기존 경계 모델과 처리 흐름 재사용

**Decision**: 새 입력의 경계만 기존 여섯 min/max 필드에 합류시킨다. 기존 옵션만 사용하면 현재 변환 경로를 따른다. 검색 조건 밖의 원시 문자열이나 입력 방식은 SearchCriteria·Result에 저장하지 않는다.

**Rationale**: 사이트 티어 조건 전달, 미제공 제외, 정렬, 추천, 조건 출력이 이미 해당 필드를 소비한다. 티어를 별도 수치 필터로 추가하면 003 정책과 충돌한다. 출력도 기존 `min_tier=...` 등의 필드로 의미를 보존할 수 있다.

**Evidence**: `cli.py:_present`는 여섯 필드를 순회한다. `service.py:Picker._run`은 수집 후 `filter_listing`을 호출한다. `selection.py:filter_listing`은 티어 범위가 있을 때 미정·미확인만 제외하고 확정 티어 수치를 다시 비교하지 않는다. 정답률·정답 제출 수에는 양 끝 포함 비교를 사용한다.

**Alternatives considered**: 새 필터 엔진, 수집기 변경, 별도 명령, 입력 표기 원문을 결과에 추가하는 방식은 사용 가치에 필요하지 않다.

## R6. 검증과 헌장 정합성

**Decision**: 실제 CLI 입력을 고정 공급자와 연결해 18개 기본 조합·복수 지표·오류·출력을 검증한다. 기존 필터/서비스/DOM 회귀를 재사용한다. 실사이트 확인은 선택적 통합 확인으로 분리하고, 변하는 목록에 대한 두 실행의 결과 동일성을 수용 근거로 삼지 않는다.

**Rationale**: 변경은 입력 표기이므로 동일한 관측 목록에서 조건과 결과가 같은지가 핵심이다. 추천은 적격 후보·개수·중복·부족을 검증하면 되며 무작위 표본 일치는 필요하지 않다. 입력 검사 실패 시 공급자 호출 목록이 비어 있는지를 관측하면 조회 전 실패를 증명할 수 있다.

**Evidence**: `tests/test_cli.py:source_factory`가 생성·시작·조건·종료 호출을 기록하고 실제 기본 브라우저 열기를 막는다. `test_site_tier_bounds_and_observed_tier_output`, `test_zero_and_missing_statistics_output` 등 기존 행동 검증을 확장할 수 있다. 003 계획과 004 명세는 영구 캐시 제외라는 기존 사용자 합의를 명시한다.

**Alternatives considered**: 새 파서 함수를 그대로 복제하는 단위 테스트, 모든 문법을 DOM 테스트로 반복, 시간에 따라 달라지는 실사이트 개수 고정, 새 캐시 구축은 배제한다.

## 조사 결론과 남은 항목

모든 기술 선택을 확정했다. 새 외부 의존성이나 사용자 확인이 필요한 미결정 사항은 없다. Python·Typer 동작은 현재 잠금 환경에 대한 확인이며, 잠금 밖의 과거 Typer 버전까지 실행 검증했다고 해석하지 않는다. Phase 1은 이 결정에 따라 작성하며 구현·제품 테스트는 후속 단계다.
