# Feature Specification: 티어·정답률·정답 제출 수 범위 옵션 추가

**Feature Branch**: `004-add-range-options`

**Created**: 2026-10-28

**Status**: Draft

**Input**: User description: "기존 옵션을 유지하면서 --accepted 500..1000 형태의 범위 옵션을 추가하고, --tier와 --rate까지 포함해 스펙 문서를 작성한다."

사용자는 조회와 추천에서 지표마다 최솟값·최댓값 옵션을 따로 입력하는 대신 하나의 옵션으로 범위를 지정한다.
예를 들어 `jpick list --tier 9..13 --rate 40.5..80 --accepted 500..1000`으로 세 조건을 함께 입력한다.
양 끝을 포함하고 한쪽 경계를 생략할 수 있으며, 기존 명령과 검색 조건의 의미를 유지한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 하나의 옵션으로 각 지표의 범위 지정하기 (Priority: P1)

사용자는 `list`와 `recommend`에서 `--tier`, `--rate`, `--accepted`를 사용해 필요한 조건을 짧게 입력한다.

**Why this priority**: 두 경계를 지정할 때 지표마다 옵션 두 개를 반복하는 불편을 직접 줄이는 핵심 기능이다.

**Independent Test**: 같은 관측 문제 목록에 기존 표기와 새 표기를 각각 적용해 검색 조건, 적격 후보, 조회 순서와 개수가 같은지 확인한다. 추천은 무작위 개별 결과의 일치 대신 적격 후보 집합·반환 개수·중복 여부를 비교한다.

**Acceptance Scenarios**:

1. **Given** 정답 제출 수가 499, 500, 750, 1000, 1001인 문제가 있고, **When** `list --accepted 500..1000`을 실행하면, **Then** 다른 조건이 없는 경우 500, 750, 1000인 문제만 적격이다.
2. **Given** 동일한 사이트 목록과 실행 조건이 있고, **When** `list --tier 9..13`과 `list --min-tier 9 --max-tier 13`을 각각 실행하면, **Then** 같은 티어 검색 조건과 같은 조회 결과를 사용한다. 사이트가 제공한 범위 밖 확정 티어도 기존 정책대로 보존한다.
3. **Given** 정답률이 40.49, 40.5, 60.25, 80, 80.01인 문제가 있고, **When** `list --rate 40.5..80`을 실행하면, **Then** 40.5, 60.25, 80인 문제만 적격이다.
4. **Given** 세 지표를 함께 지정하려는 사용자가 있고, **When** `list --tier 9..13 --rate 40.5..80 --accepted 500..1000`을 실행하면, **Then** 기존 여섯 경계 옵션으로 지정한 것과 같은 조건·정렬 결과·표시 개수를 얻는다.
5. **Given** 같은 관측 목록에서 기존 경계 옵션으로 추천할 수 있고, **When** 각 지표 또는 세 지표를 함께 새 표기로 지정해 `recommend --count 3`을 실행하면, **Then** 같은 적격 후보 집합에서 중복 없이 추천하며 반환 개수와 부족 안내가 기존 표기와 같다.

### User Story 2 - 필요한 경계만 입력하고 기존 명령 유지하기 (Priority: P2)

사용자는 하한이나 상한만 필요할 때 해당 숫자만 남겨 범위를 입력하고, 저장해 둔 기존 명령도 계속 사용한다.

**Why this priority**: 기존 사용법과의 호환성을 보존하면서 열린 범위에도 같은 입력 규칙을 제공한다.

**Independent Test**: 두 명령 각각에서 세 옵션의 하한만·상한만·같은 경계 입력을 기존 표기와 비교하고, 서로 다른 지표의 새 표기와 기존 표기를 조합해 확인한다.

**Acceptance Scenarios**:

1. **Given** 하한만 필요한 사용자가 있고, **When** `--accepted 500..`, `--tier 9..`, `--rate 40.5..`를 각각 지정하면, **Then** 해당 지표의 기존 최솟값 옵션만 지정한 것과 같다.
2. **Given** 상한만 필요한 사용자가 있고, **When** `--accepted ..1000`, `--tier ..13`, `--rate ..80`을 각각 지정하면, **Then** 해당 지표의 기존 최댓값 옵션만 지정한 것과 같다.
3. **Given** 양쪽 경계가 같은 조건이 필요하고, **When** `--accepted 0..0` 또는 `--rate 0..0`을 지정하면, **Then** 실제 0인 값만 통과하며 미제공 지표를 0으로 간주하지 않는다. `--tier 9..9`는 기존 티어 하한·상한 9와 같은 사이트 검색 조건이다.
4. **Given** 기존 여섯 경계 옵션을 사용하는 명령이 있고, **When** 새 옵션 없이 그대로 실행하면, **Then** 같은 조건·정상 결과·입력 오류 처리를 유지하며 새 옵션으로 전환하라는 경고를 추가하지 않는다.
5. **Given** 지표별로 다른 표기를 사용하고, **When** `--tier 9..13 --min-rate 40.5 --max-rate 80 --accepted 500..`를 지정하면, **Then** 서로 다른 지표의 표기를 함께 허용하고 모든 조건을 적용한다.
6. **Given** 수치 범위 옵션을 하나도 지정하지 않고, **When** 기존 조회나 추천 명령을 실행하면, **Then** 생략한 지표에 새 필터를 추가하지 않고 기존 기본값을 유지한다.

### User Story 3 - 잘못된 범위를 조회 전에 고치고 사용법 확인하기 (Priority: P2)

사용자는 잘못된 범위나 충돌하는 옵션을 입력했을 때 어느 옵션을 어떻게 수정해야 하는지 알 수 있고, 도움말에서 올바른 표기를 확인한다.

**Why this priority**: 짧은 표기가 잘못 해석되거나 일부 조건이 무시되면 사용자가 의도하지 않은 문제를 추천받을 수 있다.

**Independent Test**: 잘못된 입력과 혼용 입력을 두 명령에 전달해 조회 시작 전 실패·종료 코드·오류 안내를 확인하고, 도움말과 README 예제가 명세와 일치하는지 검토한다.

**Acceptance Scenarios**:

1. **Given** `--accepted 1000..500`, `--tier 0..5` 또는 `--rate 0..100.1`을 입력하고, **When** 실행하면, **Then** 조회 시작 전에 종료 코드 2로 실패하고 해당 옵션과 잘못된 범위 이유를 안내한다.
2. **Given** `--accepted 500..1000`과 `--min-accepted 500` 또는 `--max-accepted 1000`을 함께 지정하고, **When** 실행하면, **Then** 값의 일치 여부나 옵션 순서와 관계없이 종료 코드 2로 거부하고 한 가지 표기만 사용하도록 안내한다. 티어와 정답률도 같다.
3. **Given** 범위 값이 `..`, `500`, `500...1000`, `500..750..1000`, 빈 문자열 또는 숫자가 아닌 경계이고, **When** 실행하면, **Then** 해당 옵션의 오류와 허용하는 범위 예시를 안내하며 조회하지 않는다.
4. **Given** 같은 새 옵션을 두 번 이상 지정하고, **When** 값이 같거나 다른 상태로 실행하면, **Then** 마지막 값 채택이나 범위 합치기 없이 종료 코드 2로 거부한다.
5. **Given** 사용자가 `list --help`, `recommend --help`와 README를 읽고, **When** 새 옵션으로 명령을 작성하면, **Then** 세 옵션의 닫힌 범위·열린 범위·허용 수치·혼용 제한과 기존 옵션 유지 여부를 확인할 수 있다.

### Edge Cases

- 두 경계가 같은 범위는 유효하다. 티어 `1..1`, `30..30`, 정답률 `0..100`, 정답 제출 수 `0..0`을 포함한다.
- `--rate 47.45..47.45`는 입력한 소수 경계를 반올림하지 않으며 기존 정답률 경계와 동일하게 해석한다.
- 티어·정답 제출 수의 소수, 모든 지표의 음수, 정답률의 100 초과와 티어의 1~30 밖 경계를 거부한다.
- 범위 값에 부호, 쉼표, `%`, 지수 표기, 공백, 티어 이름 또는 숫자 대신 무한대·NaN을 넣으면 거부한다. 따옴표로 감싼 값에도 같은 규칙을 적용한다.
- 값 누락, 빈 값, 양쪽 경계 생략, 구분자 누락·반복·추가를 유효한 무제한 조건이나 단일값으로 추정하지 않는다.
- 새 옵션과 같은 지표의 기존 옵션은 경계가 겹치지 않는 경우에도 거부한다. 예를 들어 `--accepted 500.. --max-accepted 1000`도 오류다.
- 서로 다른 지표의 새 옵션·기존 옵션 조합은 허용하며, 새 표기의 순서는 결과에 영향을 주지 않는다.
- 필터 때문에 모든 문제가 제외되어도 기존처럼 정상 빈 결과 또는 추천 부족을 알린다.
- 새 옵션에서도 미제공 지표의 제외·미확인 표시, 범위 밖 확정 티어 보존, 수집 종료 정책은 기존과 같다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: `list`와 `recommend` 모두에 `--accepted`, `--tier`, `--rate`를 추가해야 한다. 기존 여섯 `--min-*`·`--max-*` 옵션은 계속 지원해야 한다.
- **FR-002**: 세 옵션은 `하한..상한`, `하한..`, `..상한`을 지원해야 한다. 구분자는 연속된 마침표 두 개이며, 적어도 한 경계가 있어야 한다. 숫자 하나만 쓰는 표기는 지원하지 않는다.
- **FR-003**: 지정한 경계는 모두 포함해야 하며, 생략한 경계는 해당 방향의 제한을 추가하지 않아야 한다. 하한과 상한이 같으면 유효하고 하한이 상한보다 크면 거부해야 한다.
- **FR-004**: `--accepted`의 경계는 0 이상의 정수여야 한다. 지표는 동일 사용자의 중복 정답 제출을 포함한 정답 제출 수이며 맞힌 사람 수나 전체 제출 수로 바꾸지 않아야 한다.
- **FR-005**: `--tier`의 경계는 1~30 정수여야 한다. 기존 티어 옵션과 같은 사이트 검색 조건이어야 하며, 사이트가 제공한 범위 밖 확정 티어를 수치 범위로 다시 제외하지 않아야 한다. 미정·미확인 티어의 기존 처리도 유지해야 한다.
- **FR-006**: `--rate`의 경계는 0~100의 정수 또는 소수여야 한다. 소수는 소수점 앞뒤에 숫자가 있는 십진 표기를 허용하고, 경계를 반올림하거나 `%`를 자동 제거하지 않아야 한다.
- **FR-007**: 경계 숫자는 ASCII 숫자로 입력받아야 하며, 정답률 소수점 외의 부호·기호·쉼표·공백·지수 표기·이름·비유한 값을 거부해야 한다. 티어와 정답 제출 수는 소수 표기를 거부해야 한다.
- **FR-008**: 새 옵션과 같은 지표의 기존 최솟값 또는 최댓값 옵션을 함께 지정하면 값의 일치 여부와 입력 순서에 관계없이 거부해야 한다. 새 옵션과 다른 지표의 기존 옵션은 함께 사용할 수 있어야 한다.
- **FR-009**: 각 새 옵션은 명령마다 한 번만 허용해야 한다. 같은 옵션을 반복하면 값이 같아도 거부해야 하며 합집합·교집합이나 마지막 값 우선 규칙을 도입하지 않아야 한다.
- **FR-010**: 값 누락, 문법 오류, 수치 범위 위반, 경계 역전, 혼용과 반복 오류는 모두 조회를 시작하기 전에 종료 코드 2로 실패해야 한다. 오류에는 해당 옵션과 수정 이유를 알리고, 문법 오류에는 유효한 예시를, 혼용 오류에는 충돌하는 옵션을 표시해야 한다.
- **FR-011**: 같은 관측 목록과 다른 실행 조건이 같을 때 새 표기와 대응하는 기존 표기는 같은 검색 조건·적격 후보·조회 순서·집계·추천 후보 및 부족 처리로 이어져야 한다. 추천 결과 자체의 무작위 일치는 요구하지 않는다.
- **FR-012**: 새 표기도 실제 0과 미제공을 구분해야 하며, 필터가 지정된 미제공 지표의 제외와 고유 제외 수 집계는 기존 정책을 따라야 한다. 옵션 생략은 새 필터 활성화로 해석하지 않아야 한다.
- **FR-013**: 세 범위를 함께 지정할 수 있어야 하며 사용자 풀이 조건, 정렬, 표시·추천 개수 등 기존 옵션과 같은 규칙으로 조합되어야 한다. 전체 후보 수집 후 처리와 중복 없는 추천 정책도 유지해야 한다.
- **FR-014**: `list`·`recommend` 도움말과 README는 세 새 옵션, 수치 제한, 양 끝 포함, 열린 범위, 같은 지표의 혼용 금지와 기존 옵션 유지를 설명해야 한다. 세 지표를 함께 쓰는 조회 예시와 열린 범위를 사용하는 추천 예시를 각각 하나 이상 제공해야 한다.
- **FR-015**: 결과의 조건 안내는 새 표기로 입력한 모든 경계와 생략 여부를 기존 표기와 동일한 의미로 확인할 수 있어야 한다. 기존 최솟값·최댓값 명칭으로 표시해도 되며, 입력 표기 차이 때문에 다른 조건처럼 설명해서는 안 된다.

### Key Entities *(include if feature involves data)*

- **지표별 범위 입력**: 대상 지표와 선택적인 하한·상한으로 구성되는 사용자 조건이다. 양 끝 포함이며 적어도 한쪽 경계가 필요하다.
- **검색 조건**: 티어의 사이트 검색 범위와 정답률·정답 제출 수의 필터 범위, 기존 사용자 풀이 조건을 포함한다. 입력 표기가 달라도 경계가 같으면 같은 조건이다.
- **입력 오류**: 문법·수치·경계 순서 위반이나 같은 지표의 표기 충돌·반복을 나타낸다. 사용자는 조회 전에 문제 옵션과 수정 이유를 확인한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 세 지표를 양쪽 경계로 지정하는 데 필요한 범위 옵션 수가 6개에서 3개로 50% 줄어들며, 사용자는 한 명령으로 기존과 같은 세 조건을 지정할 수 있다.
- **SC-002**: 두 명령 × 세 지표 × 닫힌 범위·하한만·상한만의 18개 기본 조합과 같은 경계·복수 지표 조합 검증에서, 새 표기와 기존 표기의 검색 조건·적격 후보·개수 및 조회 정렬 일치율은 100%다. 추천은 같은 후보에서 요청 개수 이내로 중복 없이 반환한다.
- **SC-003**: 명세의 잘못된 문법·수치 범위·경계 역전·같은 지표 혼용·새 옵션 반복 사례를 두 명령에서 검증했을 때 조회 전 거부율과 종료 코드 2 일치율이 모두 100%이며, 오류 안내에서 문제 옵션과 수정 이유를 확인할 수 있다.

## Assumptions

- 앞선 대화에서 합의한 추가 방식을 따른다. 기존 옵션을 제거하거나 사용 중단 예정으로 표시하지 않는다. 실제 기존 이름은 `--min-accepted`·`--max-accepted` 등 하이픈 표기이며 camelCase 별칭은 추가하지 않는다.
- 간결하고 일관된 규칙을 위해 단일 숫자는 지원하지 않는다. 같은 경계는 `500..500`처럼 지정한다. 숫자 두 개를 별도 인자로 받는 방식이나 복수 범위·배타 경계·티어 이름·자동 수치 보정도 범위 밖이다.
- 같은 지표의 혼용과 새 옵션 반복은 의도를 추정하지 않고 오류로 처리한다. 기존 경계 옵션 자체의 반복 처리 변경은 이번 범위에 넣지 않는다.
- 현재 [README](../../README.md)와 [003 명세](../003-align-site-listing/spec.md)의 사이트 티어 검색·미제공 지표·수집 종료 정책에 의존한다. 입력 표기 추가 때문에 이 정책이나 데이터 접근 방식을 변경하지 않는다.
- 기능의 사용성은 입력해야 하는 옵션 수와 재현 가능한 명령 시나리오로 검증한다. 별도 사용자 조사·처리 속도 개선·고정된 실사이트 결과 개수 보장은 요구하지 않는다.
- 이번 작업은 명세·품질 체크리스트·활성 기능 경로 작성까지다. 제품 코드, 도움말, README, 실행 테스트, 계획과 작업 목록의 실제 변경은 후속 단계에서 수행한다.
- 영구 캐시와 오프라인 조회는 추가하지 않는다. 헌장 III의 영구 캐시 원칙과 현재 합의한 비영구 목록 처리의 차이는 선행 기능과 동일하며 후속 계획의 정합성 검토에 기록한다.
