# Research: 사이트 목록 기준의 수집 정책

**Date**: 2026-10-22 | **Spec**: [spec.md](spec.md)

## 조사 범위와 근거

003 스펙과 [002 후속 이슈의 최신 합의](../002-improve-list-collection/post-implementation-issues.md), 현재 작업 트리의 제품 코드·회귀 자료를 조사했다.  
통계·티어 정책과 목록 완료 흐름은 별도 연구 에이전트의 읽기 전용 조사 결과를 통합했다. 이번 단계에서 실사이트를 다시 조회하거나 제품 코드를 수정하지 않았다.

| 근거 | 확인 내용 |
| --- | --- |
| `src/algorithm_problem_picker/jungol.py`의 `_SNAPSHOT`, `_wait_listing`, `_problem` | 빈 통계의 표시 근거가 추출되지 않고, 준비 판정과 정답 파서가 빈 정답을 거부한다. |
| 같은 파일의 `_LIST_UPDATE`, `_load_more`, `_collect` | 목록 영역 완료 알림 요구와 수집 루프의 재대기가 버튼 부재 종료를 막는다. |
| `src/algorithm_problem_picker/selection.py`의 `filter_listing` | 수집 예외를 제거해도 확정 티어의 요청 범위 비교가 다시 제외한다. |
| `tests/test_jungol_dom.py`, `tests/test_selection.py`, `tests/test_service.py` | 기존 정책의 실패·제외·지연 대기 기대와 유지해야 할 구조 오류·사용자 검색 경계가 공존한다. |
| 원문 실사이트 기록 | 8213번의 티어 8 배지, 10872·10697번의 명시적 빈 통계, 버튼 로딩 해제·제거를 관측했다. 수치는 당시 자료다. |

## R1. 티어 조건의 책임

**Decision**: 요청·UI 검증과 표시 티어의 유효성 검사는 유지하고, 확정 티어의 요청 범위 비교만 수집 단계와 순수 필터 양쪽에서 제거한다.  
`SearchCriteria`의 티어 입력 1~30·하한≤상한, 배지 값 0~30 및 정상 미정·미확인 처리는 유지한다. `_within`은 정답률·정답 제출 수 필터에 남긴다.

**Rationale**: 원문 합의는 사이트가 선택한 목록을 따르는 정책이다. `_collect`의 예외만 제거하면 `filter_listing`이 같은 문제를 제외한다. 표시값 보정·추가 경고도 합의에 없다.

**Alternatives considered**: 범위 밖 문제 자동 제외, 표시 티어 보정, 수집 예외만 제거, 상세 조회 보강, 전체 문제은행 재수집은 채택하지 않는다.

## R2. 명시적 빈 통계의 최소 판별

**Decision**: 기존 `rates`, `accepted`, `rateLinks`에 셀별 `rateEmpty`, `acceptedEmpty` boolean 배열을 추가한다. 각 배열은 같은 통계 셀 목록에서 만들고 `hasAttribute('data-col-empty')`로 표시 존재를 읽는다.  
새 미제공 표현은 해당 통계 셀 정확히 1개·trim 후 빈 문자열·그 셀의 명시적 빈 표시를 모두 만족할 때 인정한다. 링크 존재 자체는 정답 제출 수의 새 미제공 근거로 쓰지 않는다.

준비 판정과 파서는 같은 비공개 빈 상태 판별을 사용한다. 숫자나 기존 미제공 토큰이 있으면 해당 텍스트 규칙으로 처리한다. 빈 표시가 있어도 `0`은 `Known(0)`, 잘못된 비어 있지 않은 숫자는 파싱 오류다.  
정답률의 기존 빈 링크 예외인 `rateLinks == [문제 href]`는 호환성을 위해 유지하되 정답 제출 수로 확대하지 않는다. 명시적 빈 표시는 `Unavailable`로 표현하며 새 도메인 타입을 만들지 않는다.

**Rationale**: 현재 텍스트 배열은 셀 누락·중복을 검출하는 근거이므로 유지할 가치가 있다. 두 boolean 배열이면 실사이트에서 확인한 표시를 보존하면서 모델·공개 경계 변경을 피할 수 있다.

**Alternatives considered**: 모든 빈 문자열 허용, 임의 빈 앵커 허용, 미제공을 0으로 채우기, 숫자·오류를 빈 표시로 덮어쓰기, 별도의 통계 상태 계층 추가는 제외한다.

## R3. 준비 판정과 오류의 경계

**Decision**: 유일한 정답·정답률 셀의 정상 비어 있지 않은 텍스트 또는 허용된 미제공 표현은 행을 읽을 수 있는 근거다. 숫자·표시 자체의 유효성은 `_problem`에서 확정한다.  
마커 없는 임시 빈 정답은 준비를 기다린다. 제한 시간 내 숫자로 채워지면 실제 값을 읽고, 준비 실패·누락·중복·파싱 오류는 기존 진단 예외로 남긴다. 행 0개는 사이트의 명시적인 빈 결과가 있을 때만 정상 빈 목록이다.

**Rationale**: 준비 조건만 느슨하게 바꾸면 파서가 다시 실패한다. 반대로 모든 빈 값을 정상화하면 로딩 중 값과 구조 오류를 숨긴다.

**Alternatives considered**: 준비 단계에서 빈 값을 무조건 통과시키기, 파서에만 예외 추가, 준비 실패를 빈 검색 결과로 바꾸기는 제외한다.

## R4. 더 불러오기 완료 경로의 분리

**Decision**: 기존 비공개 `_wait_listing(previous)`의 `previous is not None`을 클릭 후 추가 로드 모드로 사용한다. 접근 오류를 먼저 확인하고, 다음 번호 링크와 더 불러오기 버튼이 모두 없으며 현재 목록을 정상 파싱할 수 있으면 그 스냅샷을 반환한다.  
이 완료 분기에는 목록 영역 `busy`, 관련 요청 집합 `_pending`, 추가 완료 알림이나 두 번 동일한 스냅샷을 별도 종료 근거로 요구하지 않는다. 임시 빈 통계의 준비와 구조·파싱 검증은 계속 적용한다.

컨트롤이 남아 있으면 기존 로딩·disabled·pending 준비 조건 및 새 고유 ID 확인을 유지한다. 버튼이 남고 새 ID가 없으면 15초 제한 후 진행 실패다. 다음 번호 링크가 있으면 최종 종료로 보지 않고 기존 페이지 분기로 진행한다. 중복 컨트롤은 오류다.  
최초·번호 페이지 탐색의 준비·안정화와 사용자 검색 완료 판정은 유지한다. 전체 대기에서 관련 요청·로딩 검사를 일괄 삭제하지 않는다.

**Rationale**: 버튼 부재 종료를 기존 전역 준비 guard 뒤에 두면 같은 대기가 다시 발생한다. 사용자 합의는 정상 현재 목록을 읽는 종료 기준이며 미래 반영을 입증하는 별도 완료 신호를 요구하지 않는다.

**Alternatives considered**: 목록 관찰 대상을 버튼으로 확대, 요청 완료를 새 필수 증거로 사용, 고정 안정화 시간 추가, 제한 시간 증가, 모든 탐색의 대기 제거는 채택하지 않는다.

## R5. 수집 루프와 관찰자 수명

**Decision**: 최초·번호 페이지·더 불러오기에서 반환된 스냅샷을 `_collect`의 다음 루프에서 소비한다. 매 반복의 무조건적인 두 번째 `_wait_listing()`은 제거한다. 스냅샷을 처리하기 전 URL·origin·경로·필터 UI와 관측된 접근 오류 검증은 유지한다.  
`_LIST_UPDATE`, 목록용 `update` 인수와 관찰자 생성·disconnect/dispose를 제거한다. `_load_more(previous)`는 클릭 후 `_wait_listing(previous)`를 호출하는 기존 비공개 경계로 남긴다.

`_USER_UPDATE`와 사용자 결과 대기에는 `JSHandle`이 계속 필요하다. import와 사용자 관찰자 정리는 보존하고, 브라우저/context 정리 및 Ctrl+C 원예외 보존도 유지한다.

**Rationale**: `_load_more`만 고치면 외부 루프가 일반 모드로 다시 기다린다. 목록용 관찰자를 남겨 새 종료 기준과 무관한 상태를 유지할 이유가 없다.

**Alternatives considered**: 완료 결과를 버리고 매번 재대기, 목록·사용자 관찰자 동시 삭제, 새 공개 완료 상태 API 추가는 제외한다.

## R6. 회귀 기대값의 정책 전환

**Decision**: 범위 밖 티어 실패·제외 테스트를 보존 성공으로 전환하고, 버튼 제거 후 지연된 행·다음 버튼을 반드시 기다리는 기대는 현재 목록 완료로 바꾼다.  
버튼 부재를 평가하는 시점의 목록을 결정적으로 구성하고, 짧은 sleep과 실행 속도에 따라 3개/4개가 바뀌는 검증을 성공 조건으로 삼지 않는다. 합성 시나리오는 실사이트 관측과 분리해 기록한다.

기존 `test_unknown_count_stops_at_first_active_filter`는 범위 밖 `Rated`도 정답률 필터까지 도달하므로 미확인 제외 수의 기대가 2에서 3으로 바뀐다. 정상 미정·미확인만 있는 서비스 사례의 적격 0·미확인 제외 1은 유지한다.  
목록 관찰자 정리 실패 테스트는 삭제된 동작에 맞춰 정리하고 추가 수집 대기 중 Ctrl+C 전파로 검증한다. 사용자 관찰자 정리·동일 핸들·지연 사용자 결과 검증은 유지한다.

**Rationale**: 기존 구현의 정책을 바꿀 때 과거 기대를 모두 유지하면 서로 반대인 수용 기준이 된다. 실제 오류·취소의 결과 금지는 계속 검증해야 한다.

**Alternatives considered**: 과거 테스트 전체 삭제, 실패 테스트를 skip/xfail로 숨기기, 지연 수치만 조정해 맞추기는 제외한다.

## R7. 범위·의존성·헌장

**Decision**: 현재 Python 3.12.13, Playwright 1.64.0, Typer 0.27.3, Rich 15.0.0, pytest 9.1.1 환경과 잠금 의존성을 사용한다. 새 라이브러리·공개 API·진행 이벤트·캐시를 추가하지 않는다.  
제품 진행 정보 전달을 바꾸지 않고 실패·취소 상태 안내와 최종 결과 미제공만 유지한다. 정답 제출 수·정답률 수치 필터, 정렬·추천, 사용자 공개 검색 및 목록 전용 접근을 승계한다.

**Rationale**: 기존 모델과 경계로 요구를 표현할 수 있다. ISSUE-003은 명시적으로 제외됐고 영구 캐시 제외는 002에서 합의한 범위를 003 스펙이 재확인했다. 헌장 III와의 차이는 계획의 정당화된 범위 예외로 기록한다.

**Alternatives considered**: 진행 콜백 재설계, 영구 캐시 도입, 상세 조회 보강, 새 데이터 접근 경로는 제외한다.
