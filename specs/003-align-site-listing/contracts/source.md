# Source Contract: 사이트 목록 정책에 따른 수집

**Spec**: [spec.md](../spec.md) | **Model**: [data-model.md](../data-model.md)

003은 002의 범위 밖 확정 티어 실패·빈 정답 셀 일괄 오류 규칙과, 더 불러오기에서 별도 종료 근거를 요구한 001/T038·T041 정책을 대체한다.  
그 밖의 공개 목록 접근·사용자 확인·번호 페이지·오류 처리 경계는 승계한다.

## 경계와 수명

- 기존 `resolve_user(handle) → UserReference`, `collect(criteria, user) → CompletedListing` Protocol을 유지한다.
- Playwright·DOM·URL 매개변수·스냅샷 필드는 공급자 내부에 둔다. 테스트용 공개 API나 추가 실행 옵션을 만들지 않는다.
- 비영구 context 1개·목록 page 1개로 순차 처리한다. 문제 상세 페이지·전체 문제은행 우회 수집은 추가하지 않는다.
- 탐색/추가 로드 시작 최소 1초 간격, 탐색 30초·준비/동작 15초 제한과 50ms 확인 간격을 유지한다.
- 성공·실패·Ctrl+C에서 브라우저를 정리하고 원래 취소 예외를 보존한다. 재시도·접근 우회·내부 응답 해독·앱 전역 상태 추출은 하지 않는다.
- 문제·사용자 매핑·storage_state·HAR·추적 자료를 다음 실행용으로 저장하지 않는다.

## 요청 조건과 티어

| 조건 | 전달·검증 |
| --- | --- |
| 일반 문제·순서 | `type=problem`, `sort=idAsc`. |
| 티어 하한·상한 | 지정한 `minTier`, `maxTier`만 전달. 입력값 1~30 및 하한≤상한 유지. |
| 미정 포함 정책 | 티어 경계가 하나라도 있으면 `unrated=exclude`, 없으면 include. |
| 공개 사용자 풀이 | 확인한 account_id를 `solvedBy`로 전달. solved는 `solvedByMode=include`, unsolved는 exclude. |
| 정답률·정답 제출 수 | 미확인 서버 옵션을 만들지 않고 수집 후 로컬 필터 적용. |

최초·번호 페이지·추가 로드 후에도 현재 URL의 origin·경로·필수 조건과 공개 필터 UI를 확인한다. 중복 값·누락·변조·다른 사용자 모드·로그인용 status 대체는 실패다.  
URL/UI의 티어 조건이 유지되는지와 실제 표시 티어가 범위 안인지의 검사는 구분한다. 정상 `Rated`의 요청 범위 차이로 실패·제외·추가 경고하지 않는다. 관측한 티어를 그대로 보존한다.

배지 `/solved/0.svg`는 Unrated, 1~30은 Rated다. 기존 검증된 무배지 미정·명시적 난이도 미확인 표현도 유지한다. 임의 배지 누락·중복·알 수 없는 경로·범위 밖 값은 구조 오류다.  
정상 미정·미확인 티어의 후보 포함·제외는 [데이터 모델](../data-model.md)의 기존 규칙을 따른다.

## 표·행·통계 추출

공개 목록의 문제·정답률 헤더로 표를 식별하고 각 일반 문제 행 내부에서 고유 문제 링크·제목·배지를 읽는다. 고정 열 번호·스타일 색상·해시 클래스에 의존하지 않는다.  
정답 제출 수는 `td[data-col="정답"]`, 정답률은 `td[data-col="정답률"]`에서 읽으며 각각 정확히 1개여야 한다. 시도 열·맞힌 사람 통계를 정답 제출 수로 대체하지 않는다.

| 스냅샷 정보 | 요구 |
| --- | --- |
| `accepted`, `rates` | 해당 셀별 trim 텍스트 배열. 셀 개수 검증 근거를 유지한다. |
| `acceptedEmpty`, `rateEmpty` | 같은 셀 목록의 `data-col-empty` 존재 여부 배열. 속성의 빈 값도 표시 존재로 읽는다. |
| `rateLinks` | 기존 정답률 빈 링크 지원을 위한 href 목록. |

### 파싱 규칙

- 정답 제출 수는 0 포함 ASCII 정수 또는 정상 천 단위 쉼표 정수다. `3145`, `3,145`는 정상이며 음수·소수·잘못된 쉼표·임의 설명은 오류다.
- 정답률은 기존의 소수·% 표현을 Decimal로 읽고 표시 정밀도를 유지한다. 다른 통계로 재계산하지 않는다.
- 기존 `-`, `—`, `미확인`, `미제공` 토큰은 Unavailable이다. 이 토큰의 합성 계약과 실제 빈 통계 관측 근거를 혼동하지 않는다.
- 새 빈 통계는 해당 셀 정확히 1개·빈 텍스트·그 셀의 `data-col-empty` 표시를 모두 만족할 때 Unavailable이다. 빈 표시만으로 비어 있지 않은 값을 덮어쓰지 않는다.
- 정답률의 기존 빈 텍스트와 `rateLinks == [해당 문제 href]` 예외는 유지한다. 정답 제출 수의 마커 없는 빈 앵커는 새 미제공 근거로 인정하지 않는다.
- 준비 판정과 `_problem`은 같은 비공개 명시적 빈 판별을 사용한다. 정상 0은 Known(0), 빈 표시가 있어도 잘못된 비어 있지 않은 숫자는 오류다.
- 마커 없는 임시 빈 값은 준비를 기다리고, 이후 표시된 실제 값을 읽는다. 준비 실패·셀 누락·중복·파싱 실패를 미제공이나 0으로 바꾸지 않는다.

## 준비·진행·종료

모든 모드에서 접근 오류·챌린지·로그인 요구·HTTP 실패를 확인하고, 행 파싱·표 식별·진행 컨트롤 중복 검증을 유지한다.  
표가 없고 버튼도 없다는 사실만으로 성공하지 않는다. 유효한 현재 행 또는 사이트가 명시한 정상 빈 검색 결과가 필요하다.

### 최초 목록·번호 페이지

기존 탐색과 일반 준비 흐름을 유지한다. 관련 요청·공개 로딩·disabled 상태를 확인하고 준비된 스냅샷의 기존 안정성 비교를 적용한다.  
명시적인 빈 통계는 준비된 값으로 인정한다. 번호 페이지는 같은 origin·문제 목록 경로, 반복 URL 금지와 새 ID 검사를 유지한다. 다음 번호 링크가 있으면 더 불러오기 버튼이 없어도 최종 종료가 아니다.

### 클릭 후 더 불러오기

기존 `_wait_listing(previous)`의 previous 집합으로 모드를 구분한다. 모드 전용 공개 상태나 외부 API를 만들지 않는다.

| 상태 | 처리 |
| --- | --- |
| 다음 링크·더 불러오기 버튼 모두 없음, 현재 목록을 정상 파싱 가능 | 현재 스냅샷으로 반환·완료. 새 ID가 없어도 정상이다. |
| 컨트롤 없음, 행 0개, 명시적 빈 검색 결과 | 정상 빈 결과로 완료. 이미 누적한 후보가 있으면 누적 후보는 보존한다. |
| 컨트롤 없음, 통계가 임시 미준비 | 해당 값 준비만 기존 제한 안에서 기다린다. 임의 미제공으로 바꾸지 않는다. |
| 버튼 있음·조작 가능·현재 목록 준비·새 ID 있음 | 새 스냅샷을 처리하고 계속 수집한다. |
| 버튼이 로딩 중 또는 disabled | 버튼 존재로 판정하고 준비를 기다린다. 종료로 해석하지 않는다. |
| 버튼 유지·새 ID 없음 | 기존 제한 후 SourceCompletenessError. |
| 다음 번호 링크 있음 | 기존 번호 페이지 분기로 진행한다. |
| 중복 버튼·중복 다음 링크·두 종류 동시 존재 | SourceSchemaError. |

컨트롤 부재의 유효한 현재 목록 반환 경로는 일반 guard보다 먼저 평가한다. 이 경로에서는 `_pending`, 목록 영역 busy 해제, 두 번 동일한 스냅샷, 별도 완료 알림을 필수 종료 증거로 요구하지 않는다.  
현재 목록을 읽을 수 있다는 검증은 유지하지만, 미래에 추가될 행·버튼을 반드시 기다리는 지연이나 별도 타이머를 추가하지 않는다. 관측되지 않은 미래 결과의 포함을 보장하지 않는다.

### 수집 루프와 관찰자

- 최초·번호 페이지·더 불러오기 분기에서 얻은 스냅샷을 다음 `_collect` 반복에서 사용한다. 무조건적인 두 번째 일반 `_wait_listing()` 호출을 제거한다.
- 스냅샷 처리 전 현재 URL·공개 필터 UI와 관측된 접근 오류 검증은 유지한다. 조건 손실이 있으면 현재 후보로 성공시키지 않는다.
- `_LIST_UPDATE`, 목록용 update 인수·completed_load 검사, `_load_more`의 목록 관찰자 생성·정리를 제거한다.
- `_USER_UPDATE`, `_update_user_page`, `_wait_user_page`와 JSHandle import는 유지한다. 사용자 검색의 결과 반영·pending/busy·관찰자 수명은 변경하지 않는다.

## 결과와 실패

고유 번호별 최초 관측을 누적하고 새 종료 기준을 만족한 뒤에만 CompletedListing을 반환한다. 정답률·정답 제출 수 필터와 정렬·추천은 이 목록에 적용한다.  
표시/추천 개수가 작다는 이유로 목록을 일찍 끝내지 않는다. 범위 밖 Rated가 수치 필터까지 도달하므로 미확인 제외 개수는 과거 정책과 달라질 수 있다.

| 오류 | 계약 |
| --- | --- |
| SourceAccessError | 탐색·접근 제한·관측된 전송 실패·요청 조건 손실. 표시 티어의 요청 범위 차이는 포함하지 않는다. |
| SourceSchemaError | 표·링크·배지·통계 구조/파싱 및 중복 컨트롤 오류. |
| SourceCompletenessError | 계속되는 목록의 진행 없음·반복 번호 페이지·추가 준비 실패. 버튼 부재 시 읽을 수 있는 현재 목록은 오류가 아니다. |
| UserResolutionError | 기존 공개 사용자 확인 실패. |
| KeyboardInterrupt | 취소를 보존하고 브라우저/context를 정리한다. |

실패·취소 시 CompletedListing이나 부분 최종 결과를 반환하지 않는다. 진행 개수 전달·누적 보존을 위한 필드·콜백·예외 정보는 추가하지 않는다.
