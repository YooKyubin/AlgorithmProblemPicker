# CLI Contract: 사이트 검색 조건과 관측값 표시

**Spec**: [spec.md](../spec.md) | **Source**: [source.md](source.md)

## 명령과 입력

기존 `jpick list`, `jpick recommend`, `jpick open`과 옵션 이름·기본값을 유지한다.

| 입력 | 규칙 |
| --- | --- |
| `--min-tier`, `--max-tier` | 사이트에 전달하는 티어 검색 경계. 정수 1~30, 하한≤상한. 표시 티어의 범위 일치를 보장하지 않는다. |
| `--min-rate`, `--max-rate` | 로컬 정답률 조건. 소수 0~100, % 기호 없이, 양 끝 포함. |
| `--min-accepted`, `--max-accepted` | 로컬 정답 제출 수 조건. 정수 0 이상, 양 끝 포함. 중복 정답 제출 포함. |
| `--status`, `--user` | all/solved/unsolved, 정확한 공개 핸들. solved/unsolved는 user 필수, all+user는 오류. |
| `list --sort` | id/difficulty/rate/accepted/random. 기본 id. |
| `list --order` | asc/desc, 기본 asc. random+desc는 입력 오류. |
| `list --limit` | 양의 정수, 기본 20. 수집 종료 기준 이후 표시 제한. |
| `recommend --count` | 양의 정수, 기본 1. 종료 기준까지 확인한 전체 적격 후보에서 선택. |

기존 solver 옵션·정렬 입력은 새 옵션 안내를 포함한 입력 오류 2로 거부한다. 새 지표 별칭으로 허용하지 않는다.  
도움말·버전·입력 오류는 공급자·브라우저를 시작하지 않는 기존 동작을 유지한다.

## 결과 의미

stdout에 번호·제목·관측 난이도·정답률·정답 제출 수·링크와 조건·개수·조회 시각을 표시한다.  
요청한 티어 경계와 실제 표시 티어를 그대로 보존한다. 표시 티어가 범위 밖이라는 이유로 오류·자동 제외·추가 경고를 출력하지 않는다.

- 티어 경계는 사이트 검색 조건이다. 정상 Rated의 로컬 요청 범위 비교를 하지 않는다.
- 티어 경계가 있을 때 정상 미정·미확인은 기존대로 제외하고, 없으면 포함한다.
- 실제 통계 0은 0, 명시적인 미제공은 ‘미확인’, 티어 미정은 ‘미정’으로 표시한다.
- 해당 지표 필터가 있는 미제공 문제는 제외하며 고유 미확인 제외 수를 stderr로 알린다. 필터가 없으면 다른 조건을 만족하는 문제를 포함할 수 있다.
- 모든 후보 제외는 정상 성공이다. list는 결과 없음을, recommend는 실제 반환 개수와 부족 수를 안내한다.
- 양방향 지표 정렬에서 미정·미확인은 마지막, 지표 동점·미확정 그룹은 번호 오름차순이다. 난이도 정렬에는 실제 표시값을 사용한다.
- 값은 각 목록 관측 시점의 정보다. 정답률을 다른 통계로 재계산하거나 미제공을 0으로 채우지 않는다.

## 수집 완료와 사용 안내

더 불러오기 버튼이 있으면 계속 수집하고, 없으면 읽을 수 있는 현재 목록으로 완료한다. 별도의 목록 영역 완료 알림을 필수로 요구하지 않는다.  
다음 번호 링크가 있으면 해당 페이지를 계속 확인한다. 실패·구조 오류 화면을 버튼 부재만으로 정상 결과로 바꾸지 않는다.

README와 관련 도움말은 다음 의미를 일관되게 안내한다.

1. 사이트 검색 결과를 따르므로 표시 티어가 요청 범위 밖일 수 있다.
2. 명시적인 빈 통계는 미제공이며 실제 0과 다르다. 해당 지표 필터의 유무에 따라 제외·미확인 표시한다.
3. 더 불러오기 종료는 버튼 부재 시 현재 목록을 기준으로 한다. 이후 지연 반영이나 사이트의 누락까지 복구한다는 보장은 없다.

별도 동의 화면·새 경고·새 옵션을 추가하지 않는다. 실제 사이트에서 지연 반영 순서가 확인되면 새 근거로 정책을 보완한다.

## 진행·종료 코드

stderr의 수집·Processing·완료·실패·취소 안내와 Ctrl+C 사용법을 유지한다. ISSUE-003의 진행 정보 전달 방식 변경과 실패·취소 누적 개수 보존은 요구하지 않는다.

| 코드 | 의미 |
| --- | --- |
| 0 | 적용된 종료 기준에 따른 정상 완료. 후보 0개·추천 부족 포함. |
| 1 | 접근·사용자 확인·구조/파싱·요청 조건 손실·실제 진행 실패 또는 명시적 open의 브라우저 전달 실패. |
| 2 | 잘못된 옵션·입력값·범위·개수·사용자 조건·기존 solver 입력. |
| 130 | Ctrl+C 취소. |

실패·취소한 실행의 최종 표·추천 결과는 stdout에 출력하지 않고 조회 브라우저를 정리한다.  
새 정책에 따라 버튼 부재로 성공한 현재 목록 결과는 실패·취소의 부분 결과로 취급하지 않는다.

## 명시적 문제 열기와 비범위

`open`은 입력한 양의 정수 번호를 입력 순서로 중복 제거해 기본 브라우저로 연다. list/recommend는 기본 브라우저를 열지 않는다.  
정상 조회·추천의 문제 상세 요청 0건, 기존 목록 전용 처리·공개 사용자 기준을 유지한다. JSON 출력·진행 옵션·영구 캐시·번호순 개수 기반 조기 종료는 추가하지 않는다.
