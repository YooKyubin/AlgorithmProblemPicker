# AlgorithmProblemPicker Constitution

## Core Principles

### I. JUNGOL에 집중

JUNGOL 문제를 검색하고 추천하는 개인용 CLI에 집중한다.
프로그래머스 지원과 플랫폼 통합은 현재 범위에 포함하지 않는다.

### II. 허용된 데이터 접근

자동 수집 허용 여부를 확인한 방식으로만 데이터를 수집한다.
내부 API의 존재를 사용 허가로 간주하지 않으며, 제공 여부와 의미가 확인된 지표만 사용한다.

### III. 로컬 데이터 우선

수집한 문제 목록은 로컬에 캐시하고, 검색·필터링·정렬·추천은 캐시를 기준으로 처리한다.
무작위 추천은 지정한 조건을 만족하는 문제에서 중복 없이 선택한다.

### IV. 단순한 구조

데이터 접근, 로컬 처리, CLI 출력을 분리한다.
현재 기능에 필요한 만큼만 구현하고, 불필요한 추상화와 미리 만드는 확장은 피한다.

### V. 명확한 동작과 검증

지원하지 않는 조건과 데이터·설정 오류는 사용자에게 명확히 알린다.
변경한 핵심 동작은 필요한 최소한의 테스트 또는 실행 확인으로 검증한다.

## 기술 방향

Python CLI로 개발한다. Typer, Rich, uv를 기본 후보로 삼고,
데이터 수집 도구는 허용된 접근 방식이 확인된 뒤 선택한다.

## 개발 절차

데이터 접근 허용 여부와 확보 가능한 항목을 먼저 확인한다.
목록 조회 → 필터링·정렬 → 무작위 추천 → 브라우저 열기 순서로 구현하고,
기능 범위나 사용법이 바뀌면 README에 반영한다.

## Governance

명세·계획·구현을 검토할 때 이 원칙의 준수 여부를 확인한다.
원칙을 바꿀 때는 변경 이유와 영향을 기록하고 이 문서를 함께 수정한다.
버전은 호환되지 않는 원칙 변경은 MAJOR, 원칙·절차 추가는 MINOR, 문구 보완은 PATCH로 올린다.
